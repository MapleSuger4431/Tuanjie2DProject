## A. 交付前功能完整性走查（编译器抓不到，必过）

**编译通过 ≠ 功能写全写对**。每批脚本写完，对照 UI 需求/设计文档静态走查这三项：

1. **需求对照（写全没有）**：把文档声明的每个交互/显示功能点列成清单（如"音量滑块实时生效""关卡列表按进度解锁"），逐条 `rg` 自查代码里真有实现、而非只字面提及。**文档有、代码无 = 未完成**。
2. **关键交互链走查（闭环没有）**：沿核心链逐环确认"输入→逻辑→**视觉表现**→状态"每步都有代码闭环。例：点击开始按钮 → `StartGame()`（有没有人调用？）→ 状态切 Playing → HUD 显示/主菜单隐藏（路由真的推这个面板？）。**任一环只写了逻辑没接显示、或只订阅没人产出，即为断链**。
3. **返回值/绑定审查（写对没有）**：关键方法的返回值是否被调用方真正使用（算完就丢 = 死输出）；绑定属性赋值处是否是唯一产出端；`SafeFind`/`SafeQ` 取到的动态元素是否有写它的代码（取了从不更新 = 死 UI）。

## B. 交付前接线/活性自检清单（逐条核对，必过）

每个脚本写完、进入 RoslynValidator 前，逐条对照（适用却没补 = 视为未完成）：

0. **🔴 HUD 数据产出端闭环（最高优先）**：每个 HUD 显示值/事件链，**都要能在代码里找到产出它的那行**（绑定属性赋值 / 游戏服务方法 / `UIFrame.SetGameState`）。只订阅不产出 = 永远是默认值。**产出端唯一性**：同一数据的产出 API 在全工程有且仅有一处调用，`rg -c` 统计调用点 >1 即可疑双重产出；订阅方只读取/显示/联动，不得再次产出。
1. **Inspector 引用字段非空**：`[SerializeField]` 指向其它组件/资产的运行依赖字段，逐个确认接线来源（场景预置/Prefab 序列化）；代码不兜底创建场景依赖。
2. **订阅必退订（成对）**：`OnSubscribe`/`OnEnable` 里订阅的每一条（含 `UIFrame.StateChanged +=`），必须在 `OnUnsubscribe`/`OnDestroy` 里成对退订。漏退订 → 面板关闭后仍收事件、重开局叠加两套监听（幽灵刷新/重复 Push 的根源）。
3. **定义了一端就必须接上另一端（机器查不到，靠走查）**：配置字段定义了就要读（SO/Inspector 字段禁止别处用同语义硬编码字面量代替）；公开方法定义了就要被调；Query/SafeFind 到的动态元素就要有更新逻辑。写完逐字段/逐方法 `rg` 确认另一端存在。

## C. 必过红线（对照 UI 产物高频翻车点）

### 面板注册名一致
`[Panel("注册名", gameId)]` 的注册名、`UIFrame.GetUIManager()` 的 `Switch/Push` 参数、`PanelNames` 常量三者必须完全一致（含大小写）。拼错 = 路由解析 0 个面板，游戏已切状态但界面不动。

### 初始面板名走常量（禁止序列化字符串）
`private readonly string _initialPanel = MyGamePanelNames.MainMenu;`——禁止 `[SerializeField] private string _initialPanel = "MainMenu"`：场景保存的旧序列化值会覆盖代码修改后的默认值。

### 面板显隐交给框架
业务脚本不直接 `SetActive` 摆弄面板树；显隐切换经 `UIFrame.GetUIManager()` 的 `Push`/`Pop`/`Switch` 或 Panel 基类的对应方法（UGUI 侧由 `_canvas.enabled` 控制，基类已处理）。自摆 SetActive 会绕过导航栈与显隐语义。

### HUD 常驻面板透明
Playing 态常驻 HUD 的根 Canvas 不得有不透明背景 Image（UGUI：Image alpha 全透明/无背景图）——否则"游戏已进入 Playing 但画面被面板盖住"。

### UI 状态流转走 UIFrame.SetGameState
游戏侧驱动 UI 状态一律调 `UIFrame.SetGameState(state)`（发布 `UIFrame.StateChanged`，HUD 基类/UIPanelRouter 订阅联动）；UI 脚本只订阅/响应，不自建状态机、不绕过 `UIFrame` 直接改面板。

### 禁止遮蔽框架事件类型
业务源码不得声明与 `Create.GameFramework` 的 `*Event` 同名的类型（RoslynValidator **UR038**）——同名会让事件订阅静默路由到错误类型。

## F. 编码规范细节（起草时按需查，工具兜底）

- **脚本类型与文件名一致**（public concrete MonoBehaviour/ScriptableObject，RoslynValidator **UR039**）；`UIGameInstaller` 与游戏脚本必须带与 GameName 一致的 namespace，防多游戏同名类误挂。
- **禁用 `Resources.Load` 系列**（RoslynValidator **UR029**）：UI 资产走直接引用/PanelRegistry 注册。
- **属性读写死代码**：被读从不赋值 / 被赋值从不读（**UR026/027**，全量集下最准）；不可达 else-if 分支（**UR028**）。
- **组件查找 null 安全**：`Instantiate`/跨对象 `GetComponent` 结果未验证即解引用（**UR048-050**）；null guard 只 return 不报错 = 静默失效（**UR050**）。用 `TryGetComponent`/`?.`/guard 后 throw/窄豁免注释。
- **MonoBehaviour 生命周期**：重写 `Awake`/`OnEnable` 注意基类职责（面板基类已认领 `OnEnable`/`OnDisable`，UIGameInstaller 用普通 `MonoBehaviour`，初始化放 `Start`）；不要 `private void` 隐式隐藏基类生命周期。

## G. 分批写脚本模式的错误处理

- **按 prompt 范围判责**：报错文件在当前范围内则必须修；范围外则仅报告阻塞，不越界修改。同一错误只记录一次。
- 当前脚本因尚未产出的外部类型/成员报错可留给后续全量部署任务；禁止添加临时 stub。
- 全量部署任务统一修复跨文件契约与全量编译错误。
- **共享类型归属（防 CS0101）**：跨脚本 enum、事件、接口、数据类由架构文档指定文件唯一定义；其它文件只引用，绝不补一份。
