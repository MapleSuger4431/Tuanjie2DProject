# 阶段 2 · 补全方法体（进入本阶段时才读本文件）

> **现在才允许 `grep` API 参考文档查签名、窄读基类声明**——因为骨架已落盘、有 checkpoint，即便某个方法单独超时，已填的方法不报废。

## 一、填充节奏：逐个/逐组 `replace`，不要一次巨型 `write_file`

- 骨架已在磁盘上 → 用 `replace` **逐个或逐组填方法体**，每次只填 1~N 个方法。每次都是小请求，远 < 301s。
- 即便某个复杂方法（如复杂绑定链、状态切换逻辑）单独超时，骨架与已填的方法已落盘、可续跑，不再全 job 报废。
- 某次 `replace` 明确失败/超时时，先读回文件刷新方法体锚点；当前方法拆小后重试，最多两次。其它已填方法不得回滚，未完成前不得直接返回 partial。
- 简单/短脚本若阶段 1 未落骨架，可在此一次 `write_file` 完整写出。

## 二、查签名的边界（本阶段唯一放开 read/grep 的地方）

1. **第一次填方法体前先做一次"本批 API 契约核对"**：从架构文档"脚本清单与业务契约"读取所选基类与框架件，再按以下顺序核对签名，命中即停止扩张：**`../unity-ui-builder/modules/ui-panel-builder/references/UIFrame-API.md`（框架/面板/导航类）与 `../unity-ui-builder/modules/ui-panel-builder/references/UIAnimation-API.md`（动效类），以框架源码与该参考文档为准**。记下准确拼写/参数后立刻 `replace` 至少一个方法体。
   - 参考文档仅可对**单一类型**定向 grep；禁止全文读取完整参考文档，也禁止换关键词反复搜索。
   - 权威参考以 `extensions/TJUIBuilder/skills/` 下文件为准（相对路径从 csharp-code-writer 技能根解析）；grep 命中 `skill-workspaces/**/skill-snapshot/**` 的同名文档为过期 eval 快照，一律忽略。
   - 自定义业务事件载荷从架构事件契约逐字使用；框架内建事件（`GameStateChangedEvent`）以 `UIFrame-API.md` 为准，不依赖架构重复抄录。
2. **生命周期与 UI 钩子属于签名硬契约，不允许靠编译试错猜测**：
   - `UIPanelBase` 子类按参考文档（UIFrame-API.md）签名覆写 `OnBind()`、`OnShow(object param)`、`OnHide()`；不要把同名 public 方法当作"框架会反射调用"的约定，不要改成无参 `OnShow()`。
   - `GameUIControllerBase`/`UGUIGameControllerBase` 的 HUD 实现按参考文档（UIFrame-API.md）使用 `QueryElements()`、`OnSubscribe()`、`OnUnsubscribe()`、`UpdateHud()` 钩子。
   - 确需覆写 `Awake`/`OnEnable`/`OnDestroy` 等 Unity 生命周期时注意基类职责（UIGameInstaller 用普通 `MonoBehaviour`，初始化放 `Start`）；不得写 `private void` 隐式隐藏基类生命周期。
3. 仅当参考文档对某钩子的 grep 确实缺失、且该钩子是本脚本核心时，才做一次窄查：先看参考文档对应类型段，再仅聚焦读取该基类声明。查到即 `replace`，不扩展研究相邻实现；仍无权威签名则停止发明 override，改用参考文档公开 API 并报告契约缺口。
4. 普通 Unity API 的公开类型或成员签名不确定时，先实现再由阶段 3 编译兜底；**UI 框架方法名、事件成员、生命周期 override 与 UI 钩子**必须先完成上面的有界核对。
5. **停滞熔断**：骨架落盘后连续 2 次只读/搜索而无 `replace`，或第二次搜索同一框架类型仍无新签名，立即停止研究并按已确认契约填下一个方法。不得用"再找一个实现"延迟所有方法体落盘。
   - ⛔ **永不读**：`Runtime/Core/UI/Boards/`（编辑器面板工具，与面板脚本无关）。

## 三、四条铁律（填充时贯穿，命名空间 `Create.GameFramework`）

1. 单一数据源：每个 HUD 显示值只有一个权威产出端（绑定属性或游戏服务），其余只订阅/读取。
2. 系统间通信走 DI：脚本间不互相持引用、不自建静态事件中心；游戏侧服务经 `UIFrame.DI` 注册/解析（如 `IGameService`）。
3. 面板显隐切换交给 UI 框架：`UIGameInstaller`/`UIFrame` 负责 Push/Switch；业务脚本不直接 SetActive 摆弄面板树。
4. 订阅必退订：`OnSubscribe`/`OnEnable` 里订阅的事件必须在 `OnUnsubscribe`/`OnDestroy` 成对退订，防幽灵面板叠加监听。

## 四、UI 框架件替换对照表（填方法体时对照——命中左列却自己写 = 视为未完成）

| 你想做的事 | ❌ 禁止自写 | ✅ 必用框架件（`Create.GameFramework`） |
|------------|-----------|----------------------------------------------|
| UI 状态/流程驱动 | 自写 `enum GameState`+单例+`ChangeState` | 游戏侧调 `UIFrame.SetGameState(state)`；HUD/路由按 `UIFrame.StateChanged`（`GameStateChangedEvent`）订阅同步 |
| 系统间通信 | A 持 B 引用 / 原生 `event Action` 跨系统 | 游戏服务经 `UIFrame.DI` 注册/解析（`RegisterSingleton<T>`/`Resolve<T>()`），UI 脚本只订阅/读取 |
| 面板显隐切换 | HUD 里 `switch(state)`/自写 UIManager | `UIGameInstaller` 订阅状态/事件后经 `UIFrame.GetUIManager()` 调 `Push`/`Pop`/`Switch`（本技能不重复实现路由） |
| 常驻 bootstrap | 自写静态实例管理 | 普通 `MonoBehaviour`（UIGameInstaller），初始化放 `Start`；跨场景常驻才由游戏侧自管单例 |
| HUD 数据显示 | Update 里每帧 `text.text = ...` 直刷 | 绑定属性 + 绑定构建器（`UGUIBindingBuilder`/`BindingBuilder`，见 UIFrame-API.md），数据变才刷新 |
| UI 点击音效 | 直接调 AudioSource / 自写 AudioManager | `UIAudioFeedback` 组件直挂（AudioSource 2D 自动管理） |
| 关卡选择网格 | 自写关卡按钮生成 | 游戏侧自建数据源 + `UGUIBindingBuilder.ToListView`（集合绑定）；关卡解锁/星级属游戏数据，经服务注入 |
| 拖拽/指针交互 | 裸 `Input.mousePosition` 轮询 | UGUI 事件系统（`EventTrigger`/按钮回调/滑动事件），非 UI 输入不属于本技能 |

> 表中省略的踩坑案例见检查清单 C 节；填充时不必读案例，认清用哪个件、照右列写即可。
