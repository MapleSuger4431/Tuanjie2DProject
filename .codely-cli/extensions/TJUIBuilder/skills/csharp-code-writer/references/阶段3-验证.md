## 一、最小人工语义审查（起草与检查的分界点）

初稿全部写完后确认：关键交互符合 UI 需求/设计文档；跨脚本公共入口存在真实调用者；HUD 显示值有唯一有效产出端；订阅在面板关闭/对象销毁时成对退订。不要用 `rg` 命中数量证明功能完成，上述四项须定向走查。其余机械项由 RoslynValidator（UR025/UR032-036 半成品左移、UR048-050 组件查找 null 安全等）与部署后编译负责；工具报告失败时再按 `references/检查清单.md` 对应小节修复。

---

## 二、RoslynValidator 全量验证（必须执行）

所有脚本写完后统一验证（**勿每改一个就编译**）：

1. 首次或不确定参数 → 先读 `.codely-cli/extensions/TJUIBuilder/tools/RoslynValidator/RoslynValidator使用指南.md`。
2. `run_shell_command` 调用（自包含单文件产物在 `.codely-cli/extensions/TJUIBuilder/tools/RoslynValidator/bin/`）：**Windows** 跑 `bin/RoslynValidator.exe`，**macOS/Linux** 跑 `bin/RoslynValidator`（无扩展名，直接执行、无需 `dotnet`；仓库默认只 ship Windows 二进制，macOS/Linux 首次需先 `./build.sh`；两者参数完全相同）。UI 脚本验证固定带 `--profile game-scripts`（启用 UR032-039/048-051）。具体参数见指南。
3. 失败 → 按错误修（小语法错用 `replace`，大结构改用 `write_file`），相同参数重验，**最多 10 次**。
4. 成功后分叉：
   - **分批写脚本场景** → 到此即完成当前任务。其它范围外类型依赖错误逐项按当前批次合同精确归因，**禁止忽略全部 CS0103 或注入通用 stub**。**不进第三、四节。**
   - **改 bug/调参/加功能场景** → 继续第三节部署。

## 三、部署 + 等 Domain Reload（仅改 bug/调参/加功能场景；写脚本场景整节跳过）

**部署**：`context/games/{GameName}/GameScripts/` → `Assets/Games/{GameName}/Scripts/`
- 步骤二的 Roslyn 全量编译已阻断 context 内重复 FQN。执行部署型工具一行调用 `Create.GameFramework.TJGameScriptsDeploy.Run("{GameName}")`（包 `Editor/UIBuildTools`，`execute_csharp_script`；原 `references/scripts/deploy_scripts.cs` 已移植部署化）：整目录拷贝**全部** `.cs` → 在任何 Import/编译前硬检查目标侧 missing/extra/case/content → 逐个导入 → 触发编译。部署 EditorScript 禁止启动或等待外部进程。
- ⚠️ **必须全量部署**：对象是源目录**当前全部** `.cs`（含早先轮次/其他来源），不是"只本次会话写的"。
- 🔴 **禁止裸 `Copy-Item`**（refresh 已关，纯拷贝不被 Unity 感知、不进编译）；**禁用 `AssetDatabase.Refresh()`**（全量重扫，违反全局禁令）。报告不一致 → 补齐重跑至完全一致。
- ⚠️ 用本技能自己的部署工具 `TJGameScriptsDeploy.Run("{GameName}")`。

**等 Domain Reload + 验证**（部署后 Unity 自动触发；Reload 完成前执行脚本会致 `Assembly-CSharp` 类型不可见 CS0246）：
  1. 调用 `start_compilation_pipeline`；该同步 action 自带 clear → compile → read 闭环，返回即编译+Reload 已完成，**以返回内嵌的 `console.entries` 为准，禁止追加 `unity_console clear/get` 或自行轮询**。仅当 Unity 工具明确报告 Bridge 实际断开/陈旧时，调用 `unity_refresh` 后重试原调用。
  2. `System.Type.GetType("{Namespace.CoreClass}, Assembly-CSharp") != null` 确认类型可用（类名取本游戏实际核心类，如 UIGameInstaller）。False → 检查导入与编译错误后重走上述编译边界；不得把 `unity_refresh` 当作类型重试或常规 Reload 步骤。
  3. console 无 error 且类型可用 → 方可执行后续步骤。

> 🚫 本技能只跑 RoslynValidator 与上面的部署后编译。**prompt 明确要求只写不部署时，禁止调 `unity_editor.start_compilation_pipeline`/`request_compile`**；完整编译留给后续全量部署任务。

## 四、写完后的 Play 冒烟（仅改 bug/调参/加功能场景）

> 分批写脚本场景已在第二节结束，不到这里。首轮开发的整体冒烟由后续集成验证任务统一执行。

**编译通过 ≠ 改对了**——UI 遮挡（游戏已进入 Playing 但面板仍盖住画面）、面板不显示（Canvas/sortingOrder/注册名错）、绑定空引用这类编译和 Play 都不报错的问题，唯有进 Play 实跑能抓：

1. 进 Play 前确认场景已挂 UIRoot + UIGameInstaller + PanelRegistry（缺失则先补齐场景挂载再冒烟——挂载属 `ui-panel-builder` Stage 02 的交付物）。
2. 用 `exec_runtime_script` 进 Play 并做结构化断言（**Play 模式严禁轮询等待**）：初始面板可见（面板树 `activeInHierarchy` / 根 Canvas `enabled`）、切到 Playing 后 HUD 可见且主菜单隐藏、关键按钮回调可触发（直接调游戏 API，不模拟输入）。
3. 返回结构化事实（`visible`/`enabled`/注册名等），不以截图代替断言；发现"状态与可见面板脱节"时回查 `[Panel]` 注册名与状态路由（见 `../unity-ui-builder/modules/ui-panel-builder/references/game-doctor-checks.md` 相关检查项）。
