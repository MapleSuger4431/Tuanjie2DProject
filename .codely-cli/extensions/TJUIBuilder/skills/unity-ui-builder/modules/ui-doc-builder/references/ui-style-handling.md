# UI 风格方向处理规则

> 本文件是 `ui-doc-builder`（`unity-ui-builder` extension 内部模块）的配套参考，详细说明当 `UI参考图分析.md` 存在时，如何在 UI设计文档.md 中应用风格参数。

## 核心原则：图生图为主，风格由参考图决定

视觉参考模式下（`UI参考图分析.md` 存在时，无论来源是用户上传参考图还是 AI 生成参考图，均经 ui-style-reference 处理），**图生图是主路径**——颜色、质感、形状、风格全部由参考图决定。UI参考图分析.md 的核心价值是：
1. **布局信息**：面板结构、元素位置、尺寸比例；以 OpenCV 组件树的父子关系和相对父级百分比为准，根坐标仅用于诊断
2. **图生图配置**：保真度、裁剪映射、构图方式。透明 PNG 可标记为 `direct_use`，AI 生成参考图与用户上传参考图走同一 ui-style-reference 流程
3. **文生图回退风格参数**（条件性）：仅当存在裁剪失败/override/缺失组件时

**不需要从参考图提取配色/质感/组件样式等风格维度来驱动图生图**——这些由参考图本身决定。仅在文生图回退场景下，风格参数才有实际用途。

## 1. 读取与解析

必须检查 `context/games/{GameName}/UI参考图分析.md` 是否存在：

- **若存在**：读取并解析以下章节，将参数注入到 `UI设计文档.md` 对应章节：
  - **布局结构**（必须读取）：面板布局表、布局参数（信息密度、间距、圆角、对齐）
  - **元素尺寸比例**（必须读取）：用于 UI设计文档.md 中的元素尺寸规划
  - **图生图配置**（必须读取）：保真度、参考图路径映射、组件裁剪映射
  - **文生图回退风格参数**（条件读取）：仅当该章节存在时读取。格式为「回退组件风格表」——每个回退组件单独列出所需风格维度，不做全面提取。下方附「图片生成风格指引」（仅含回退组件的面板类型）
- **若不存在**：Agent 根据游戏整体美术风格自行规划 UI 视觉设计，所有 UI 元素需要对应生成图片。

## 2. 布局与尺寸注入规则

当 UI参考图分析.md 存在时，使用提取的布局和尺寸参数作为 UI 设计的主要依据：

- 面板布局表（背景层 + 内容层）→ 替代 Agent 自行决定的布局结构
- 布局参数（信息密度、间距、圆角、对齐）→ 替代 Agent 自行决定的布局参数
- 元素尺寸比例 → 替代 Agent 自行决定的元素尺寸

写入 `UI设计文档.md` 的 §3.1 布局参数和 §3.2 面板布局表。

## 3. 风格参数注入规则（条件性）

**仅当 UI参考图分析.md 包含「文生图回退风格参数」章节时**，使用该章节的风格参数。该章节采用「按组件精准提取」格式——每个回退组件单独列出所需风格维度，不做全面提取。

> ⚠️ `quality=contaminated`（leaf）的组件不需要文生图回退风格参数——图生图以透明 PNG 为输入，风格由透明 PNG 决定。只有 `text2img_fallback`（无可用参考图）才需要文生图回退风格参数。

**读取方式**：从「回退组件风格表」中，按组件名查找所需维度和提取值：
- 如果 UI设计文档.md 中某个图片需求的组件名在回退组件风格表中有对应条目 → 使用该条目的风格维度值
- 如果 UI设计文档.md 中某个图片需求不在回退组件风格表中 → 使用图生图（该组件有裁剪，或 `quality=contaminated` 走图生图移除污染），风格由参考图决定

**注入规则**（按回退组件逐个注入）：

| 回退组件的所需维度 | UI设计文档.md 注入位置 |
|-------------------|---------------------|
| 配色（主色、强调色等） | §3 UI 总体设计 颜色方案 + 对应图片的视觉描述 |
| 按钮样式 | §3 UI 总体设计 按钮风格 + 对应按钮图片的视觉描述 |
| 图标风格 | §3 UI 总体设计 图标风格 + 对应图标图片的视觉描述 |
| 卡片风格 + 材质 | §3 UI 总体设计 卡片/弹窗风格 + 对应图片的视觉描述 |
| 信息栏风格 | §3 UI 总体设计 信息栏风格 + 对应图片的视觉描述 |

**图片生成风格指引**：如果回退组件风格表下方有「图片生成风格指引」（通用视觉基线 + 按面板类型风格组），写入 UI设计文档.md §13 文生图回退风格参数章节，供文生图回退组件的 prompt 构建。仅列出包含回退组件的面板类型，无回退组件的面板类型不需要列入。

### 3.1 无参考图面板派生样式注入

当 UI参考图分析.md 包含「无参考图面板派生样式」章节时（视觉参考模式下，UI需求.md 中存在参考图未覆盖的面板），ui-doc-builder 必须：

1. **读取风格描述**：从「通用视觉风格描述」提取通用视觉基线，从「无参考图面板文生图风格指引」提取每个无参考图面板的文生图风格描述
2. **注入 §3 style_guidance**：将通用视觉基线写入 `style_baseline`，将每个无参考图面板的风格描述写入 `panel_type_styles[面板类型]`，确保 ui-image-generator 文生图路径 D 的 prompt 能消费这些风格描述
3. **注入 §13**：若同时存在其他文生图回退组件，将无参考图面板的风格描述与回退组件风格合并写入 §13；若无其他回退组件，仍须为无参考图面板写入 §13（因为 §13 是 ui-image-generator 读取 style_guidance 的来源之一）
4. **布局参数不在此章节注入**：无参考图面板的布局参数（位置/尺寸/间距）由 ui-doc-builder 在 §3.1 布局参数和 §11 元素列表中根据面板功能自行规划，不从「无参考图面板派生样式」提取

**当 UI参考图分析.md 不包含「无参考图面板派生样式」章节时**（所有面板均有参考图覆盖）：不需要额外处理，所有面板走图生图。

**当 UI参考图分析.md 不包含「文生图回退风格参数」章节时**（所有组件均可图生图，包括 `quality=contaminated` 的 leaf 组件）：
- 风格参数由参考图在图生图时直接提供，不需要在 UI设计文档.md 中详细描述
- UI设计文档.md §3 UI 总体设计 仍需简要描述 UI 风格方向（供 builder 参考），但不需要完整的 style_baseline + panel_type_styles 格式
- 配色/质感等细节由 builder 在编写 USS 时从参考图直接获取

在 UI设计文档.md §3 UI 总体设计的「UI 风格」描述中注明"基于用户参考图风格（图生图模式）"。

## 4. 复合 UI 部件图片拆分

编写 UI设计文档.md §15 图片清单时，必须检查每个 UI 元素是否为复合部件（进度条、滑块、开关、下拉框、分段控制器、Tab 栏等）。

- 复合部件的静态框架（边框、阴影、纹理）和动态内容（填充宽度、滑块位置、开关状态）必须拆分为独立条目
- 静态框架图的视觉描述必须注明"中心区域透明，用于动态填充"
- 动态部分放在 UXML 元素的「样式要点」列中，不生成图片

复合部件拆分规则：进度条、滑块、开关、下拉框、分段控制器、Tab 栏等复合部件的静态框架和动态内容必须拆分为独立条目。

## 5. UI 风格方向的覆盖范围

UI参考图分析.md 仅覆盖**视觉样式**（配色、圆角、阴影、材质、纹理等）和**布局结构**。
UI设计文档.md 中的**结构与功能**部分（元素列表、UXML 结构、数据绑定、导航关系、DI 注册等）仍由 Agent 根据游戏玩法需求规划，不受参考图影响。

## 6. UI 资产获取优先级

视觉参考模式下（UI参考图分析.md 存在且包含图生图配置），UI 资产获取优先级为：

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 1 | 用户导入 | 用户自行提供的图片（最高优先级） |
| 2 | AI 生成（图生图/文生图） | 有透明 PNG 的组件走图生图；contaminated 透明 PNG 走图生图移除污染（`quality=contaminated`）；裁剪失败/缺失/art_text 拆分文字层走文生图（`text2img_fallback`） |

无视觉参考时（`UI参考图分析.md` 不存在），优先级为：用户导入 > AI 生成。**所有视觉性 UI 元素一律规划 AI 生成图片（文生图）**，除非用户明确要求纯 USS。

**UI设计文档.md 中的体现**：
- §11 每个界面的元素列表中，需 AI 生成图片的元素标注 `ai_generate: true` 及图片尺寸和视觉描述
- §15 资产清单中列出所有 AI 生成图片条目（类型为"图片"，含文件名、路径、视觉描述、`is_segmentation` 标注）
- UI 元素允许复用图片：设 `reuse_from` 为代表元素的 `name`、`crop_path` 为 `reuse_from:{代表元素name}`、`source` 保持 `ai_generate`；该元素在 §15 和 `image_requirements.json` 中仍需列出条目，但 Stage 02 不会单独生成（Path B），Stage 03 也不复制文件——USS 直接引用代表组件的图片路径（`url("Images/{代表元素name}.png")`）
- 按钮交互状态（hover/pressed）仍由 USS 伪类实现，不生成状态图片

### `is_segmentation` 判定规则（§15 资产清单）

按 `UI参考图分析.md` 的 `node_id` 判定：`node_id == "background"`（Step 8.5 全屏背景节点）→ `false`；其余全部 → `true`。
