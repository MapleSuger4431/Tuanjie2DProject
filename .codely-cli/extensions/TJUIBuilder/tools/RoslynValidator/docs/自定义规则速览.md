# RoslynValidator 自定义规则速览

> 从零到一，为 Unity 项目新增一条代码分析规则。

---

## 1. 核心概念

| 概念 | 职责 | 何时使用 |
|------|------|----------|
| **DiagnosticAnalyzer** | 规则容器，声明"我关注什么语法节点" | 每条规则对应一个类 |
| **DiagnosticDescriptor** | 规则元数据（ID、消息、严重性） | 在 Analyzer 内定义为 `static readonly` 字段 |
| **Register\*Action** | 告诉编译器"遇到 X 节点时回调我" | `Initialize()` 中注册 |
| **SyntaxNodeAnalysisContext** | 回调参数，含当前节点 + SemanticModel | 回调方法签名 |
| **SemanticModel** | 语法树 → 符号表的桥梁 | 需要类型/引用解析时使用 |

### 两条路径，两种精度

```
语法层（快，只看结构）          语义层（慢，但精确）
  SyntaxNode                     SemanticModel
  ├─ 节点类型 (SyntaxKind)       ├─ GetSymbolInfo() → 解析引用
  ├─ 文本内容 (Identifier)       ├─ GetTypeInfo()  → 获取类型
  └─ 父/子节点导航               └─ GetDeclaredSymbol() → 获取声明
```

**原则**：能用语法层判断的，不要用语义层（性能更优）；需要精确判断类型/继承关系时，必须用语义层。

## 2. 新增规则的三步流程

### Step 1：创建 Analyzer 类

文件位置：`.codely-cli/extensions/TJUIBuilder/tools/RoslynValidator/Analyzers/` 下新建 `.cs` 文件。

```csharp
using System.Collections.Immutable;
using Microsoft.CodeAnalysis;
using Microsoft.CodeAnalysis.CSharp;
using Microsoft.CodeAnalysis.CSharp.Syntax;
using Microsoft.CodeAnalysis.Diagnostics;

namespace RoslynValidator.Analyzers
{
    [DiagnosticAnalyzer(LanguageNames.CSharp)]
    public class MyCustomAnalyzer : DiagnosticAnalyzer
    {
        // ① 定义规则描述
        public static readonly DiagnosticDescriptor Rule = new(
            id: "UR030",                              // 规则 ID（见编号规范）
            title: "规则标题",
            messageFormat: "报告消息，可用 '{0}' 占位",
            category: "Performance",                  // Architecture | Performance | Correctness | Deprecation | Convention
            defaultSeverity: DiagnosticSeverity.Warning,  // Error | Warning | Info | Hidden
            isEnabledByDefault: true);

        public override ImmutableArray<DiagnosticDescriptor> SupportedDiagnostics
            => ImmutableArray.Create(Rule);

        // ② 注册回调：声明你关心什么
        public override void Initialize(AnalysisContext context)
        {
            context.ConfigureGeneratedCodeAnalysis(GeneratedCodeAnalysisFlags.None);
            context.EnableConcurrentExecution();
            context.RegisterSyntaxNodeAction(Analyze, SyntaxKind.InvocationExpression);  // ← 选对 SyntaxKind
        }

        // ③ 编写检测逻辑
        private static void Analyze(SyntaxNodeAnalysisContext ctx)
        {
            var node = (InvocationExpressionSyntax)ctx.Node;
            var symbol = ctx.SemanticModel.GetSymbolInfo(node).Symbol;
            if (symbol is not IMethodSymbol method) return;   // null 保护

            if (/* 匹配条件 */) 
            {
                ctx.ReportDiagnostic(Diagnostic.Create(Rule, node.GetLocation(), method.Name));
            }
        }
    }
}
```

### Step 2：注册到 Program.cs

在 `LoadCustomAnalyzers()` 方法中添加一行：

```csharp
static ImmutableArray<DiagnosticAnalyzer> LoadCustomAnalyzers()
{
    var analyzers = new List<DiagnosticAnalyzer>
    {
        new Analyzers.ForbiddenMethodAnalyzer(),
        // ... 已有分析器 ...
        new Analyzers.MyCustomAnalyzer(),       // ← 新增
    };
    return ImmutableArray.CreateRange(analyzers);
}
```

## 3. 选择注册方式

根据你要检测的内容，选择对应的注册方式：

| 检测目标 | 注册方式 | SyntaxKind / SymbolKind | 示例 |
|----------|----------|------------------------|------|
| 方法调用 | `RegisterSyntaxNodeAction` | `InvocationExpression` | `Foo()` |
| 成员访问 | `RegisterSyntaxNodeAction` | `SimpleMemberAccessExpression` | `a.b` |
| 对象创建 | `RegisterSyntaxNodeAction` | `ObjectCreationExpression` | `new Foo()` |
| == / != 比较 | `RegisterSyntaxNodeAction` | `EqualsExpression` / `NotEqualsExpression` | `x == null` |
| 赋值 | `RegisterSyntaxNodeAction` | `SimpleAssignmentExpression` | `x = 5` |
| 类/结构体声明 | `RegisterSymbolAction` | `NamedType` | `class Foo` |
| 字段声明 | `RegisterSymbolAction` | `Field` | `private int x;` |
| 方法声明 | `RegisterSymbolAction` | `Method` | `void Update()` |

**语法层 vs 符号层**：
- `RegisterSyntaxNodeAction`：遍历语法树节点，回调参数为 `SyntaxNodeAnalysisContext`（含 `ctx.SemanticModel`）
- `RegisterSymbolAction`：遍历符号表，回调参数为 `SymbolAnalysisContext`（无需语义查找，直接拿到 `ISymbol`）

## 4. 常用匹配模式

### 4.1 判断方法属于哪个类型

```csharp
var symbol = ctx.SemanticModel.GetSymbolInfo(invocation).Symbol;
if (symbol is not IMethodSymbol method) return;

// 精确匹配（推荐）
if (method.Name == "Find" && method.ContainingType?.Name == "GameObject")
```

### 4.2 判断类型继承关系

```csharp
bool InheritsFrom(INamedTypeSymbol? type, ITypeSymbol baseType)
{
    while (type != null)
    {
        if (SymbolEqualityComparer.Default.Equals(type, baseType)) return true;
        type = type.BaseType;
    }
    return false;
}

// 用法
var monoType = ctx.Compilation.GetTypeByMetadataName("UnityEngine.MonoBehaviour");
if (monoType != null && InheritsFrom(type, monoType)) { ... }
```

### 4.3 判断是否在特定方法内

```csharp
var enclosing = invocation.Ancestors()
    .OfType<MethodDeclarationSyntax>().FirstOrDefault();
if (enclosing?.Identifier.ValueText == "Update") { ... }
```

### 4.4 检查特性标注

```csharp
bool HasAttribute(ISymbol symbol, string name)
    => symbol.GetAttributes().Any(a =>
        a.AttributeClass?.Name == name ||
        a.AttributeClass?.Name == name + "Attribute");

// 用法
if (!HasAttribute(field, "SerializeField")) { ... }
```

### 4.5 类型比较（⚠️ 必须用 SymbolEqualityComparer）

```csharp
// ❌ 错误
if (type1 == type2) { ... }

// ✅ 正确
if (SymbolEqualityComparer.Default.Equals(type1, type2)) { ... }

// ✅ SpecialType 可直接比较
if (type.SpecialType == SpecialType.System_String) { ... }
```

## 5. 规则编号规范

| 范围 | 用途 |
|------|------|
| UR001–UR009 | API 限制规则（方法调用、成员访问、类型使用） |
| UR010–UR019 | 正确性与性能规则（null 检查、Update 性能、Tag 比较等） |
| UR020–UR029 | 代码结构规则（顶级语句等） |
| UR100–UR199 | 架构约束规则 |
| UR200–UR299 | 性能优化规则 |
| UR300–UR399 | 命名/编码规范规则 |

## 6. 严重性约定

|--------|------|------|
| **Error** | "禁止" | 必须修复，阻断编译 |
| **Warning** | "不建议" | 应修复，不阻断编译 |
| **Info** | "建议" | 可选改进 |
| **Hidden** | — | IDE 可感知但不显示 |

## 7. 调试技巧

1. **SemanticModel 返回 null 符号**：编译器无法解析（缺少 DLL 引用、代码有语法错误），做好 `if (symbol == null) return;` 保护
2. **GetTypeByMetadataName 返回 null**：类型名拼写错误或未引用对应 DLL，用 `if (type == null) return;` 保护
3. **规则不触发**：检查 `SyntaxKind` 是否选对（如 `a.b` 是 `SimpleMemberAccessExpression` 不是 `IdentifierName`）
4. **规则误报太多**：增加语义层过滤（如判断 `ContainingType` 是否为 Unity 类型），不要仅依赖方法名字符串匹配
5. **性能优化**：在 `RegisterCompilationStartAction` 中查找目标类型（闭包缓存），避免每次回调都调用 `GetTypeByMetadataName`

## 9. 完整示例：禁止在 FixedUpdate 中使用 transform.position

```csharp
[DiagnosticAnalyzer(LanguageNames.CSharp)]
public class FixedUpdateTransformAccessAnalyzer : DiagnosticAnalyzer
{
    public static readonly DiagnosticDescriptor Rule = new(
        id: "UR060",
        title: "禁止在 FixedUpdate 中访问 transform.position",
        messageFormat: "在 FixedUpdate 中访问 '{0}'，请缓存到 Awake/Start 中",
        category: "Performance",
        defaultSeverity: DiagnosticSeverity.Warning,
        isEnabledByDefault: true);

    public override ImmutableArray<DiagnosticDescriptor> SupportedDiagnostics
        => ImmutableArray.Create(Rule);

    public override void Initialize(AnalysisContext context)
    {
        context.ConfigureGeneratedCodeAnalysis(GeneratedCodeAnalysisFlags.None);
        context.EnableConcurrentExecution();
        context.RegisterSyntaxNodeAction(Analyze, SyntaxKind.SimpleMemberAccessExpression);
    }

    private static void Analyze(SyntaxNodeAnalysisContext ctx)
    {
        var access = (MemberAccessExpressionSyntax)ctx.Node;

        // 1) 只关心 .position / .rotation / .localPosition 等
        var name = access.Name.Identifier.ValueText;
        if (name is not ("position" or "rotation" or "localPosition" or "localScale")) return;

        // 2) 语义过滤：确保是 Transform 上的属性
        var symbol = ctx.SemanticModel.GetSymbolInfo(access).Symbol;
        if (symbol?.ContainingType?.Name != "Transform") return;

        // 3) 检查是否在 FixedUpdate 中
        var method = access.Ancestors().OfType<MethodDeclarationSyntax>().FirstOrDefault();
        if (method?.Identifier.ValueText != "FixedUpdate") return;

        ctx.ReportDiagnostic(Diagnostic.Create(Rule, access.GetLocation(), access.ToString()));
    }
}
```
