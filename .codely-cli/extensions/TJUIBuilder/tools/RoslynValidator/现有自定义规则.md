# 现有自定义规则

## 游戏脚本完整性硬门禁

- **UR025 (Error)**：注释 trivia 含占位词，且方法是单一常量返回。guard return 后有真实计算不会误报。普通 `SuppressWiringCheck` 不可绕过；仅接受 `SuppressWiringCheck UR025 reason:<原因>`。
- **UR032–UR036 (Error，仅 `--profile game-scripts`)**：分别拦截 `NotImplementedException`、仅占位注释的空方法、占位常量/default getter、占位空核心方法、TODO `NotSupportedException/Exception` stub。排除 abstract/interface/generated 与合法空 Unity hook。
- **UR038 (Error，仅 `--profile game-scripts`)**：从编译引用的 `Create.GameFramework` 命名空间动态收集全部 public `*Event` class/struct，禁止游戏源码声明同名顶层类型。
- **UR039 (Error，仅 `--profile game-scripts`)**：public、具体、非泛型、非 generated 的顶层 `MonoBehaviour`/`ScriptableObject` 文件名必须等于类型名；辅助类型、abstract/generic、partial 与 generated 文件不误报。

RoslynValidator 内置若干 Unity 反模式分析规则，通过 `--rules` / `-r` 参数启用。规则以 `Analyzers/` 下的 `DiagnosticAnalyzer` 类实现，由 `Program.cs` 的 `LoadCustomAnalyzers()` 注册（**不是**运行时从 `custom-rules.json` 加载——该 JSON 仅作清单索引文档）。

> **用词约定**：Error 级别使用"禁止"，Warning 级别使用"不建议/疑似"。

## 豁免机制

UR025~UR030 规则支持 `// SuppressWiringCheck` 豁免：
- UR028：在**触发行**加 `// SuppressWiringCheck`
- UR025：**方法体内**含 `SuppressWiringCheck`
- UR026/UR027：在属性**声明行**加 `// SuppressWiringCheck`

UR048/UR049/UR050 使用**语义级**豁免，不读 `SuppressWiringCheck`；只有以下情况不报：
- **同 GameObject 且 `[RequireComponent(typeof(T))]` 已保证**：编译器沿类型（含基类链）查 `[RequireComponent]`，命中即不再检查 `GetComponent<T>()` / `GetComponentInChildren<T>()` / `GetComponentInParent<T>()` 的解引用。
- **`TryGetComponent` 成功分支**：`if (x.TryGetComponent(out T c)) { c.… }` 不报，调用者已显式承担验证。
- **`?.` / `??` / `??=`**：`lookup()?.M`、`x ?? fallback`、`x ??= fallback` 都不构成未验证解引用。
- **明确的 null guard 后抛出配置异常**：`if (c == null) throw new InvalidOperationException($"{prefab.name} missing {typeof(T)}");` 让缺失 prefab contract 在加载期就响亮暴露，不属于静默失效，不报 UR050。
- **带原因的窄 suppression**：仅在确实无法靠上述任一表达时，在触发行、被报行或它们所属语句的 leading trivia 上加
  `// ComponentLookupExemption: reason=<非空原因>`。
  没有非空原因（冒号后空白）不报豁免，UR048 仍会触发——`reason=` 必须与原因同行。

UR050 仅按 guard 是否 throw 判定"是否静默"，故上述豁免中只有"`guard` 后 throw"与"reasoned suppression"对其有效；同对象 `[RequireComponent]` 与 `TryGetComponent` 本来就不会走到 UR050 分支。

## 精度说明（UR026/UR027）

UR026/UR027 的读/写统计依赖"编译看到全部引用方"。RoslynValidator 在**多 agent 并行（2a）阶段可能只传入本批文件**，此时跨文件的读/写不可见，可能误报——遇误报用声明行 `// SuppressWiringCheck` 豁免；**全量文件集（2b 部署后）判定最准**。其余规则均为单文件内可判定，无此约束。

## 精度说明（UR048/UR049/UR050）

UR048 只在**高置信来源**（`UnityEngine.Object.Instantiate()`）报 Error；用户自定义同名类型或静态 `Instantiate` 不升级为 UR048。对一般跨对象查找用 UR049 Warning、对静默 guard 用 UR050 Warning。来源只在同一方法体内沿不可重赋值的本地变量传播，最多 3 跳；超过边界不推断为高置信来源。

UR049/UR050 仅作用于 `GetComponent<T>`/`GetComponentInChildren<T>`/`GetComponentInParent<T>()` 的解引用与 guard，不会被 `TryGetComponent`、`?.`、真实 coalesce `??`、coalesce assignment `??=` 混淆。

UR048/UR049/UR050 的语义豁免依靠 type-level `[RequireComponent]` 与 syntax 形态（guard-throw、`?.`、`??`、`TryGetComponent`、reasoned suppression），经得起多 agent 2a 阶段只编译部分文件的情形；不再需要 `SuppressWiringCheck`。reasoned suppression 必须给出非空 `reason=`，空白视为格式错误、失去豁免效果，避免误把占位注释当成豁免。

## 规则详情

### UR025 — 占位常量返回

方法体同时含 (1) 占位/待补注释关键词（`占位`/`TODO`/`FIXME`/`placeholder`/`临时`/`待补`/`需补充`/`2b 阶段`/`先返回`/`暂时`）且 (2) `return` 字面量常量（数字/`true`/`false`/`null`/`default`/负数字面量）。半成品方法，语义恒错。

**修复**：补全方法真实逻辑。

### UR026 / UR027 — 属性数据流

- **UR026**：`public { get; set; }` 自动属性被读取却全工程从未被赋值——属性不被序列化（Inspector 改不了），永远停默认值。
- **UR027**：`public { get; private set; }`/`{ get; protected set; }` 自动属性被内部赋值却全工程从未被读取——"算了没人用"的死输出。

用 `IOperation` 精确区分读/写（复合赋值 `+=` 既读又写、自赋值 `X = Clamp(X)` 右值算读）。

### UR028 — 不可达 else-if 分支

`if/else-if` 链中较晚分支的条件（按顶层 `&&` 拆成子句集合）包含较早分支的全部子句，则 else-if 仅在前序为假时进入、故恒为假、分支内是死代码。含 `||` 的分支不判定。

**修复**：调整分支顺序（更具体的条件放更宽松的之前），或修正条件。

### UR030 — 框架单例不应用 FindObjectOfType 查找

游戏侧框架（游戏编排 extension）可提供 `MonoSingleton<T>` 作为单例基类（管理器/配置型 bootstrap 继承它）。本 UI 包（cn.tuanjie.create.ui）**不内置** `MonoSingleton<T>`；本规则按语义识别 `Create.GameFramework.MonoSingleton<>` 派生类型，仅供游戏侧重新引入该基类时生效，期间游戏代码用 `FindObjectOfType<T>()` 去拿这些本就是单例的实例，属于"框架已提供、却手写等价运行时查找"的反模式：每次全场景遍历比 O(1) 的 `.Instance` 慢，且绕开了框架单例的唯一性/生命周期保证。

**判定（语义级、精准不误伤）**：仅当查找方法的泛型实参 `T` 的**基类链里确实含 `Create.GameFramework.MonoSingleton<>`** 时才报警。因此 `FindObjectOfType<UIDocument>()` 等非单例合法用法不会误报。
覆盖方法：`FindObjectOfType` / `FindObjectsOfType` / `FindAnyObjectByType` / `FindFirstObjectByType` / `FindObjectsByType`（含 `UnityEngine.Object.` 限定形式）。

**修复**：`MonoSingleton<T>.HasInstance ? MonoSingleton<T>.Instance : null`（或直接 `T.Instance`）。
**豁免**：触发行加 `// SuppressWiringCheck`。
