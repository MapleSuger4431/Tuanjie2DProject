## 1. 闭环定义（V0.1.0 的范围）

V0.1.0 只交付**一条**可玩可回的链路：

```
启动 → 主菜单 → 选关 → 第一关 → 通关 → 回到选关 →（回到主菜单）
```

判定闭环成立的三条标准：

1. **进得去**：从主菜单点一次「开始游戏」后，不需要任何手工操作就能进到第一关并看到棋盘。
2. **过得掉**：第一关存在一条确定性通关解，AI 能走到终点并弹出通关结算。
3. **回得来**：通关后能回到选关界面，且**能再次进入关卡继续玩**（闭环可重复，不是一次性）。

三条均已实测通过（第 3 条在修复 7.1 之后通过）。

## 4. 逐跳实现落点

### 4.1 Bootstrap → MainMenu（自动，无玩家操作）

- 入口：`Assets/Scripts/Core/GameBootstrap.cs` `Start()` → `BootstrapAsync().Forget()`
- 顺序：`GameContext.Instance` 初始化 → `SaveService.Load()` → `await` 本地化初始化 → 切场景
- 切场景：`SceneTransition.LoadSingle(ScenePaths.MainMenu, onFailed)`
- 本地化等待已做防呆：`InitializationOperation` 完成后句柄会被 Addressables 释放，必须先判 `IsValid() && !IsDone` 再 await，并 try/catch —— 失败也要继续切场景
- 实测：进入 Bootstrap 到切走约 0.3s

### 4.2 主菜单 → 选关

- 入口：`Assets/Scripts/View/MainMenuPanel.cs` `OnInit` 中 `newGameButton.onClick`
- 跳转：`SceneTransition.LoadSingle(ScenePaths.LevelSelect, onFailed)`
- 主菜单其余按钮：继续游戏=占位日志；说明内容/设置=`UIModule.Show<...>`（Popup 层）；退出=`Application.Quit()`

### 4.3 选关 → 详情 → 第一关

- 节点生成：`LevelSelectPanel.BuildNodes()`，由 `LevelSelectModel.Levels` 表驱动（5 关，`sceneName` 为 `Level_01`~`Level_05`），锚点定位
- 解锁规则：`IsUnlocked(levelId) => levelId <= 1 || 前一关星级 >= 1` —— **V0.1.0 只有第 1 关可点**
- 点节点：`UIModule.Show<LevelDetailPanel>((object)def, UIPaths.LevelDetailPanel)`（payload 必须 `(object)` 强转，否则命中 path 重载被吞）
- 详情「进入」：`LevelDetailPanel.OnEnterClicked()`，拼路径后**先预检** `SceneUtility.GetBuildIndexByScenePath(path) < 0` → 未登记就只打 Warning 并关闭弹窗（现象：点了没反应）；已登记则 `SceneTransition.LoadSingle(path)`

### 4.4 关卡内：BoardRuntimeDriver 拉起 HUD

- `Assets/Scripts/Board/BoardRuntimeDriver.cs` `Start()` → `UIModule.Show<BoardRuntimePanel>(path: UIPaths.BoardRuntimePanel)`
- 面板生命周期：`OnInit` 建按钮/绑事件 → `OnShow` 取 Model 并订阅 `ObservableValue`（面板在 `Start` 之前就被 Show，因此 Model 缓存必须放 `OnInit`）
- 面板根 Stretch 全屏；三块占位白板（TopBar / BottomBar / RightPanel）对齐 `BoardScreenLayout.OperationRect`

### 4.5 通关判定（第一关的确定性解）

| 项 | 值 |
|---|---|
| 棋盘 | 10×10，起点左下 `(0,0)`，终点右上 `(9,9)` |
| 方块上限 | 30（随边长线性插值，10×10→30） |
| 可覆盖 | 空/路/火/冰；**起点、终点、山地不可覆盖** |
| AI 决策 | 只查四邻 1 格，禁 180° 掉头，按偏好顺序取第一个可行；无候选即判负 |
| 默认偏好 | 右 → 左 → 上 → 下（铺路阶段可调序，Play 后锁定） |

**实测通关解**：铺底行 `(1,0)…(9,0)` + 右列 `(9,1)…(9,8)` 共 17 块（≤30），终点不铺。默认偏好下 AI 一路向右到 `(9,0)` 再一路向上到 `(9,9)`，**18 步判胜**。

## 5. 返回（出关卡）的四条路径

| 出口 | 位置 | 行为 | 实现 |
|---|---|---|---|
| 返回选关 | 右上角 | 切场景回 LevelSelect | `BoardRuntimePanel.OnBackToLevelSelectClicked` → `SceneTransition.LoadSingle(LevelSelect)` |
| 重新开始 | 右上角（返回左侧） | **不重载场景**：还原预设地形 + 重抽方块 + AI 回起点 + 计时归零 + 阶段回 Building | `BoardRunModel.RestartLevel()` |
| 重玩此关 | 结算面板 | 同上 + 关闭结算面板 | `LevelResultPanel.OnRetryClicked` |
| 回到选关界面 | 结算面板 | 切场景回 LevelSelect | `LevelResultPanel.OnBackToSelectClicked` |

关卡内两个右上角按钮若预制体未回填，由 `EnsureBackButton()` / `EnsureRestartButton()` 现场创建（角锚定，`EnsureRestartButton` 必须后调用）。

### 5.1 为什么切场景必须走 SceneTransition

`UIRoot` 默认 `DontDestroyOnLoad`，挂在它分层 Canvas 下的面板**不会随旧场景卸载消失**，直接 `SceneModule.LoadSceneSingle` 会让选关界面整块压在关卡上。

`SceneTransition` 双保险：

1. `LoadSingle` 加载**前**先 `CloseAllPanels()`（清理必须早于新场景 `Start` 里 Show 的面板）
2. `RuntimeInitializeOnLoad(AfterSceneLoad)` 订阅 `sceneLoaded`，任何绕过门面的 Single 加载也收一次

收面板遍历全部 `UIRoot` 实例 + 递归子树，先 `UIModule.HidePanel(type)`，再对仍激活的孤儿面板兜底隐藏并 LogWarning。

## 7. 已修缺口与遗留问题

### 7.1 ✅ 已修：通关返回后再进同一关，运行态残留 `Settled`

- 现象：二次进入 `Level_01` 时 `BoardRunModel` 阶段 = `Settled`、结果 = `Win`、步数 = 18、AI 停在 (9,9)，而棋盘已用方块已被场景重建归零——「铺路完成」「Play」都点不动，进得去玩不了。
- 成因：`BoardContext` 跨场景常驻，`BoardRunModel.OnInitialize`（内含 `ResetRun`）只在 Context 首次创建时执行一次；`ResetRun` 原本只在 `BoardResized` 时触发，重进关卡并不经过它。
- 修复：`Assets/Scripts/Board/BoardRuntimeDriver.cs` 的 `Start()` 在 Show 面板前调 `BoardContext.Instance.GetModel<BoardRunModel>().ResetRun()`。地形由场景自身 `ApplyPreset` 重建，`ResetRun` 只管运行态与秒表，两者不重叠。

### 7.2 ✅ 已实现：通关 = 1 星，记录随存档持久化

V0.1.0 星级口径拍板为**通关即 1 星**（策划案三星制里的「到达」星；金币 / 限时两星未实现）。落点：

| 环节 | 实现 |
|---|---|
| 记录真源 | `LevelProgressModel`（`Game.Model`，实现 `ISavableModel<LevelProgressData>`，随存档文件持久化，**已废弃 PlayerPrefs**） |
| 星级 | `LevelProgressModel.GetBestStars(id)` → 有记录 1 星，否则 0 |
| 写入时机 | 只在 Win：`BoardRuntimePanel.OnRunFinished` → `RecordClearForCurrentLevel()` → `LevelProgressService.RecordClearForCurrentScene(用时, 步数)` |
| 关卡 id | 由当前场景名反查选关表（`LevelProgressService` 内部），新增关卡只要 `sceneName` 对得上 |
| 解锁 | `LevelSelectModel.IsUnlocked(id) => id <= 1 || HasRecord(id - 1)` |
| 破纪录 | `RecordClear` 返回是否刷新最短用时，作为 payload 传给 `LevelClearPanel` 展示 |

## 8. 回归验证配方（改完链路后照此复测）

1. **一定要冷启动**：先停 Play，让活动场景停在 Bootstrap，再跑运行时脚本。在已跑过的会话里 `SceneManager.LoadScene(Bootstrap)` 重载会打断启动链（GameBootstrap 不再触发），表现为「Bootstrap 卡住不切 MainMenu」。
2. **铺路绕开随机**：不要依赖抽块运气，直接用数据层铺确定的路：
   ```csharp
   var single = new TileShape("probe", Color.white, TileType.Land, new[] { Vector2Int.zero });
   for (int x = 1; x <= 9; x++) board.TryCover(new Vector2Int(x, 0), single);
   for (int y = 1; y <= 8; y++) board.TryCover(new Vector2Int(9, y), single);
   ```
3. **点按钮**：反射取面板私有序列化字段后 `button.onClick.Invoke()`，不要用虚拟鼠标注入（残留虚拟设备会污染 `Mouse.current`，且只能重启编辑器恢复）。
4. **面板开关判据**用 `panel == null || !panel.gameObject.activeInHierarchy`，**不要看 `IsOpen`**（`destroyOnHide` 默认 true 时 Hide 走销毁，不清 `IsOpen`）。
5. **顺序**：铺路 → 直接 `Play()`（方向偏好已删，「铺路完成」按钮已移除，铺路阶段即可点）→ 等 `Result != None`（10×10 关 18 步 × 0.2s ≈ 3.6s，留 15s 余量）→ 等 `LevelClearPanel`。
6. **切换加重试**：多人/多会话同时用 Bridge 时，`SceneModule` 会报「Single 场景加载进行中，拒绝新的 Single 加载」而静默失败（现象：点了没反应）。把「点按钮 → 等目标场景」包成重试 3 次（每次等 8s、间隔 1.2s）即可穿过；起步用原生 `SceneManager.LoadScene` 而不是 `SceneTransition`，可避开他人的记账冲突。
7. **必测项别漏「再进一次」**：只验证「能不能通关」会漏掉运行态残留这类问题，每次都跑到「回选关 → 再进 → 再通关」。
