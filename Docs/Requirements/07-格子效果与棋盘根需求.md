## 1. 范围

- 格子数据从「单层」升级为「通行层 + 效果层」两层叠加。
- 效果的多态体系（接口 / 抽象基类 / 具体效果资产）与「AI 踏入即触发」的执行机制。
- **棋盘根**（`BoardRoot`）：整盘数据的运行时聚合节点、跨格联动的唯一查询入口、刷新时机。
- 本版两个基础效果：**强制转向**、**传送门**。
- **不包含**：AI 元素属性（火人 / 冰人，06 篇 RB-09 尚未实现）、元素转换类效果、暂停与结算面板（复用 03 篇定义）。

## 2. 设计总览

### 2.1 两层叠加模型

每个格子恒由**两层**构成，两层互相独立、各自可空：

```
┌─────────────────────────────────┐
│ 效果层  TileEffect   （0 或 1 个）│  ← 决定「走上去会发生什么」
├─────────────────────────────────┤
│ 通行层  TileType     （必有）     │  ← 决定「能不能走」
└─────────────────────────────────┘
```

- **通行层**沿用现有 `TileType`（`Void / Land / Fire / Ice / Mountain / Start / Goal`），判定口仍是 `TileTypeInfo.IsPassable`。
- **效果层**是本版新增，**不改变通行性**：带传送门的格子本身仍是一块普通可走的路。
- 效果层**可为空**（多数格子为「无效果」），即「两层叠加」指的是层与层之间叠加，**不是**一格挂多个效果。
  - 一格最多 1 个效果（用户 2026-10-18 拍板，推翻 06 篇里「不可叠加」的含糊表述，明确为单层）。

### 2.2 多态效果（ScriptableObject 资产）

> 用户 2026-10-18 拍板：效果用 **ScriptableObject 资产**实现多态，不用 `[SerializeReference]`。

```csharp
// 接口：效果对外的唯一契约
public interface ITileEffect
{
    string DisplayName { get; }   // 中文名，日志 / 调试用
    Sprite Icon { get; }          // 格子上的叠加图标，为空则不画
    void OnEnter(TileEffectContext ctx);
}

// 抽象基类：所有效果的资产基类，字段即效果参数
public abstract class TileEffect : ScriptableObject, ITileEffect
{
    [SerializeField] string displayName;
    [SerializeField] Sprite icon;
    public string DisplayName => displayName;
    public Sprite Icon => icon;
    public abstract void OnEnter(TileEffectContext ctx);
}

// 具体效果：新增一个效果 = 新建一个子类 + 建一个 .asset，零改现有代码
public sealed class ForceTurnEffect : TileEffect
{
    [SerializeField] MoveDirection direction;   // 上 / 下 / 左 / 右
    // OnEnter: ctx.Result.ForcedNextDirection = direction;
}

public sealed class PortalEffect : TileEffect
{
    // OnEnter: 经 ctx.Board 找最近的另一个传送门 → ctx.Result.TeleportTo
}
```

**关键约束（SO 方案的头号坑）**：`ScriptableObject` 资产是**全局共享**的，
效果在运行期产生的任何状态（如「这个传送门已经用过了」）**一律不许写进 SO 字段**，
否则会跨格、跨关、跨 Play 会话污染，且退出 Play 后不自动还原。
所有运行时状态一律存在**棋盘根**维护的状态表里，效果执行时通过 `ctx.Board` 读写（见 3.3）。

### 2.3 棋盘根（BoardRoot）

> 用户 2026-10-18 原话：每次落盘或铺路都要把整盘数据刷新一次，全部归拢到「棋盘根」；
> AI 行走时任意两格要联动，就通过这个根互相获取位置。

`BoardRoot` 是一个挂在棋盘物体（与 `BoardGridView` 同物体）上的 MonoBehaviour，是：

| 职责 | 说明 |
|---|---|
| **数据聚合** | 持有全盘每格的运行时对象 `BoardCellRuntime[]`（坐标 + 通行层 + 效果层 + 效果是否已消耗 + 视图引用） |
| **唯一查询入口** | 对外只暴露 `IBoardQuery` 查询方法；效果实现**只拿到 `ctx.Board`**，不持有任何格子的直接引用 |
| **联动中枢** | 跨格查找（如「找最近的另一个传送门」）只在这里做 |
| **状态宿主** | 效果的运行期状态（消耗标记等）存在这里，随重开一并复位 |

```
        ┌──────────────┐
        │  BoardRoot   │  ← 棋盘根：唯一真源门户
        └──────┬───────┘
   Refresh()   │   IBoardQuery
   ┌───────────┼────────────┐
   ▼           ▼            ▼
BoardModel  BoardTile[]  效果状态表
(通行层+效果层  (视图)      (consumed[])
 纯数据真源)
```

**与现有 `BoardModel` 的关系（避免两套真源）**：
- `BoardModel` 仍是**纯数据真源**，本版新增一条与 `_tiles[]` **平行**的 `_effects[]` 数组。
- `BoardRoot.Refresh()` 每次从 `BoardModel` 拉数据 + 从 `BoardTile` 拉关卡预置效果，**全量重建**自己的运行时数组。
- `BoardRoot` 不反向写 `BoardModel`；它只维护「效果是否已消耗」这类运行期状态。

## 3. 数据模型与规则

### 3.1 格子两层

| 层 | 字段 | 类型 | 取值 | 决定 |
|---|---|---|---|---|
| 通行层 | `type` | `TileType` | 7 种，必有 | 可通行 / 可覆盖 |
| 效果层 | `effect` | `TileEffect`（SO 引用） | 任意效果资产或 `null` | 踏入后触发什么 |

- 起点 `Start` / 终点 `Goal` / 山地 `Mountain` 同样可以有效果层（MVP 建议留空，规则上不禁止）。
- 效果的**参数**写在 `.asset` 上（如强制转向的方向），因此同类型不同参数需要不同资产：
  强制转向需要 4 个资产 `Force_Up / Force_Down / Force_Left / Force_Right`。

### 3.2 效果层来源（用户拍板：两种都要）

| 来源 | 配置方式 | 说明 |
|---|---|---|
| **关卡预置** | 场景里 `BoardTile.effect` 直接拖资产（Inspector 原生支持，SO 方案的主要优势） | 关卡设计者摆好的固定机关 |
| **方块附带** | 方块每格随机时按权重抽（扩展 `BoardTilePoolConfig`） | 玩家铺路时铺出效果 |

方块附带的抽取沿用现有 `BoardTilePoolConfig` 结构，在每个 `LevelPool` 里加一层效果权重表：

```csharp
[Serializable]
public class WeightedEffect
{
    public TileEffect effect;   // null 表示「无效果」，作为兜底项
    public int weight;          // 0 = 不参与抽取
}
```

- 只有列进表的效果才可能抽到；「无效果」项权重最大即多数格子无效果。
- 起点 / 终点恒不参与抽取（方块也铺不到它们）。

### 3.3 棋盘根运行时

```csharp
public sealed class BoardRoot : MonoBehaviour
{
    struct CellRuntime
    {
        public Vector2Int coord;
        public TileType type;       // 通行层（来自 BoardModel）
        public TileEffect effect;   // 效果层（BoardModel 覆盖值 ?? BoardTile 预置值）
        public bool consumed;       // 效果是否已消耗（传送门用过即置 true）
        public BoardTile view;      // 视图引用，供图标刷新
    }

    CellRuntime[] _cells;

    // —— IBoardQuery：效果实现唯一能用的查询面 ——
    public bool InBounds(Vector2Int cell);
    public TileType TypeAt(Vector2Int cell);
    public TileEffect EffectAt(Vector2Int cell);
    public bool IsConsumed(Vector2Int cell);
    public void Consume(Vector2Int cell);          // 标记该格效果已消耗
    public bool TryFindNearestPortal(Vector2Int from, out Vector2Int target);
    public IEnumerable<Vector2Int> CellsWithEffect();
    public Vector3 CellToWorld(Vector2Int cell);   // 委托 BoardGridView
}
```

`TryFindNearestPortal` 口径（用户 2026-10-18 拍板）：

1. 候选 = 全盘所有「效果层是 `PortalEffect` 且 `consumed == false` 且 `≠ from`」的格子。
2. 按**曼哈顿距离** `|dx| + |dy|` 升序取最近。
3. 距离并列时按 `(y, x)` 坐标序取第一个，保证结果**唯一可复现**。
4. 候选为空 → 不传送，效果不触发，AI 正常停留在该格（等同普通路格）。

### 3.4 效果上下文与结果

效果不直接操作 AI，只**改写结果结构**，由 `BoardRunModel` 统一应用——保证效果无法绕过核心规则（掉头禁令、胜负判定）。

```csharp
public struct TileEffectContext
{
    public BoardRoot Board;     // 棋盘根：跨格联动唯一入口
    public Vector2Int Cell;     // 本次触发的格子
    public AiPawnState Pawn;    // AI 只读快照：位置 / 来路 / 前进方向 / 步数
}

public sealed class TileEffectResult
{
    public Vector2Int? TeleportTo;          // 瞬移目标（传送门）
    public MoveDirection? ForcedNext;       // 下一步强制方向（强制转向）
    public bool ClearIncoming;              // 清空来路记录
    public bool Stop;                       // 立即停下（判负）
}
```

`AiPawnState` 是 `BoardRunModel` 每步构造的**只读快照**，MVP 含：当前格、来路格、上一步方向、步数。
（AI 元素属性待 RB-09 实现后扩进此结构，届时「属性转换」类效果即可按同一契约接入。）

## 4. 效果规则

### 4.1 触发时机与结算顺序

**唯一时机**：AI **踏入**某格后（`BoardRunModel.Step()` 移动完成之后）立即结算一次。

结算顺序（本版固定）：

```
1. 选方向（强制方向 > 偏好方向，禁止掉头）→ 移动到目标格
2. 目标格 == 终点 → 判胜，结束（终点格不结算效果）
3. 取目标格效果：
   · 无效果 / 已消耗 → 跳过，本步结束
   · 有效果 → 构造 ctx → effect.OnEnter(ctx) → 拿回 result
4. 应用 result（顺序固定）：
   a. TeleportTo 有值 → 位置瞬移到落点，清空来路，前进方向不变（见 4.3）
   b. ForcedNext 有值 → 记为下一步的强制方向
   c. Stop → 立即判负
5. 落点格**不再结算**其自身效果（用户拍板：不连锁，天然防 A↔B 无限互传）
```

> 「落点不再触发效果」同时适用于传送落点。因此一步之内最多触发 **1 个**效果，不存在连锁与死循环。

### 4.2 强制转向（ForceTurnEffect）

| 项 | 规则 |
|---|---|
| 触发 | AI 踏入后，下一步被**强制**朝该方向移动一格 |
| 优先级 | **最高**——高于偏好方向，也高于掉头禁令（可破例走回来路格；06 篇待定项取「允许」） |
| 参数 | `MoveDirection direction`，写在资产上，需建上 / 下 / 左 / 右 4 个 `.asset` |
| 消耗 | **不消耗**，可反复触发（每次踩到都生效） |
| 边界 | 强制方向指向越界或不可通行格 → AI 停下 → 判负（不崩溃、不穿墙） |

### 4.3 传送门（PortalEffect）

| 项 | 规则（用户 2026-10-18 逐条拍板） |
|---|---|
| 触发 | AI 踏入后传送到**最近的另一个**传送门格 |
| 最近度量 | **曼哈顿距离**；并列按 `(y, x)` 坐标序取第一个，结果唯一 |
| 无配对 | 场上没有第二个**未消耗**的传送门 → 效果不触发，该格等同普通路格，AI 正常通过 |
| 前进方向 | 传送后**保持原前进方向不变**（不影响下一步的偏好顺序） |
| 来路 | 传送后**清空来路记录**（避免落点被掉头禁令卡死） |
| 落点 | 落点格**不再结算**其自身效果 |
| 失效 | **配对后两端同时失效**——从 A 传到 B，A 与 B 一起标记为已消耗，之后都变普通路格 |
| 对称性 | 两个门**完全等价**，无主副/进出之分，双向可传 |
| 无参数 | 传送门效果资产**无字段**，全场共用一个 `Portal.asset` 即可 |

> 「已消耗」状态存在**棋盘根的状态表**里（不是 SO 上），随重开复位。
> 一关若有 4 个门，则最多发生 2 次传送。

### 4.4 AI 单步流程改造

现有 `BoardRunModel.Step()` 改为：

```csharp
var from = aiCell.Value;
var direction = _forcedDirection ?? PickByPreference(from);   // 强制方向优先
// 强制方向下不查掉头禁令；常规候选仍排除 _previousCell
...
移动 → 终点判胜 → 结算效果 → 应用 result → 更新 _forcedDirection / _previousCell
```

- `_forcedDirection` 是用完即清的一次性字段：本步由它选出方向后立刻置空，除非本步落点效果又写入了新的强制方向。
- 传送导致的位移**不计入步数**（`stepCount` 只在普通移动时 +1）——待定项，见第 9 节。

### 4.5 棋盘根刷新时机（用户明确要求）

| 时机 | 触发方 |
|---|---|
| 关卡加载完成（`ApplyPreset` 之后） | `BoardGridView.Start` |
| **每次落盘成功**（`TryCover`） | `BoardModel.BoardCovered` 事件 |
| **重新开始本关**（`RestorePreset`） | `BoardRunModel.RestartLevel` |
| 棋盘尺寸变化（`BoardResized`） | 重建后 |
| 运行期每一步结束 | **只更新状态位**（已消耗标记），不整盘重建 |

- 前四种走 `Refresh()` **全量重建**；最后一种走轻量 `MarkConsumed()`，避免每步重建整盘（见非功能需求）。
- 效果状态（consumed）在 `Refresh()` 中**不重置**（一次落盘不该让传送门复活），只在关卡加载与重开时随 `ResetEffectStates()` 清空。

## 5. 扩展一个新效果（开发清单）

效果是整个游戏最主要的扩展点，新增一个效果**不得改动任何现有类**：

1. 新建 `XxxEffect : TileEffect`，实现 `OnEnter(ctx)`（只写参数字段 + 改写 `ctx.Result`）。
2. `Assets > Create > 棋盘 > 效果 > Xxx` 建一个 `.asset`，填中文名、图标、参数。
3. 需要按格不同参数就多建几个 `.asset`（同强制转向的上/下/左/右）。
4. 想让方块随机出它 → 加进 `BoardTilePoolConfig` 对应关卡的 `effects` 权重表。
5. 想在关卡里摆它 → 直接拖到 `BoardTile.effect`。

需要跨格联动时，一律走 `ctx.Board` 的查询方法；**新效果不得持有格子引用、不得直接改 `BoardModel`、不得改 AI 状态**，只能填 `result`。

## 6. 功能需求

---

### RE-01 格子两层数据模型（P0）
- **需求**：格子数据由「通行层 `TileType`」与「效果层 `TileEffect`」两层构成，两层独立，效果层可为空、最多 1 个。效果层**不改变通行性**。
- **验收**：`BoardModel` 有与 `_tiles[]` 平行的效果数组并提供 `EffectAt(cell)`；无效果格 `EffectAt` 返回 `null`；给任意格挂上传送门资产后，该格仍可被 AI 正常踏入。

### RE-02 效果接口与抽象基类（P0）
- **需求**：实现 `ITileEffect` 接口与 `TileEffect : ScriptableObject` 抽象基类（含 `displayName` / `icon` 字段与抽象 `OnEnter`）。
- **验收**：新建子类并实现 `OnEnter` 后即可作为资产使用；未实现 `OnEnter` 的子类编译不过。

### RE-03 棋盘根 BoardRoot（P0）
- **需求**：实现 `BoardRoot`（挂 `BoardGridView` 同物体），持有全盘 `CellRuntime[]`，对外提供 `TypeAt / EffectAt / IsConsumed / Consume / TryFindNearestPortal / CellsWithEffect / CellToWorld` 查询。
- **验收**：效果实现中**只能**通过上述方法访问其它格子；`TryFindNearestPortal` 在曼哈顿距离并列时结果稳定可复现（同输入同输出）。

### RE-04 棋盘全量刷新（P0）
- **需求**：按 4.5 的时机表，`BoardRoot.Refresh()` 从 `BoardModel` 全量重建运行时数组（通行层 + 效果层 + 视图引用）。
- **验收**：连续放置 10 块后，棋盘根内任意格的通行层与 `BoardModel.TypeAt` 逐格一致；效果层与写入值一致；刷新后已消耗标记不被重置。

### RE-05 效果来源 · 关卡预置（P0）
- **需求**：`BoardTile` 的 `effect` 字段改为 `TileEffect` 资产引用（**替换现有 `CellEffect` 枚举字段**），Inspector 可直接拖拽。
- **验收**：场景里给 3 个不同格分别拖入 `Force_Up` / `Force_Left` / `Portal`，进 Play 后棋盘根读到的效果与配置一致；旧 `CellEffect` 枚举字段已移除且场景无数据丢失（需执行迁移，见 RE-15）。

### RE-06 效果来源 · 方块附带（P1）
- **需求**：`BoardTilePoolConfig` 每个 `LevelPool` 增加 `List<WeightedEffect> effects`（含 `null` 兜底项），方块每格随机时按权重抽效果并随铺设写入。
- **验收**：把某关效果表配成「无 ×9 / 传送门 ×1」后铺 1000 格，传送门出现比例 ≈10%（±5%）；权重 0 的效果从不出现；未列进表的效果从不出现。

### RE-07 效果层覆盖规则（P0）
- **需求**：方块铺到已有格子时**整格覆盖**——通行层与效果层一起被方块带的值改写（方块该格无效果则清空效果层）。关卡预置的效果若不想被覆盖，由 `BoardTile.pinEffect` 勾选钉死（钉死格保留预置效果）。
- **验收**：在带预置传送门的格上铺一块「无效果」方块 → 效果层被清空；勾选 `pinEffect` 后再铺 → 传送门仍在。

### RE-08 效果触发与结算顺序（P0）
- **需求**：按 4.1 固定顺序结算；终点格不结算效果；一步之内最多触发 1 个效果，落点不再连锁。
- **验收**：构造 A（传送门）↔ B（传送门）相邻互传场景，AI 从 A 传到 B 后**停在 B** 不再回传，不出现无限循环、栈溢出或帧率骤降。

### RE-09 强制转向效果（P0）
- **需求**：实现 `ForceTurnEffect`（参数 `MoveDirection`），并提供上 / 下 / 左 / 右 4 个资产。优先级高于偏好方向与掉头禁令；不消耗，可反复触发。
- **验收**：①四个方向各自生效；②即便偏好方向可走，仍走强制方向；③强制方向指向来路格时允许破例掉头；④指向不可通行格 / 越界 → 停下判负且不崩溃。

### RE-10 传送门效果（P0）
- **需求**：实现 `PortalEffect`（无参数，全场共用一个资产）。按 3.3 找最近未消耗门；无配对则不触发；传送后**前进方向不变**、**清空来路**、**落点不再结算**。
- **验收**：①两个门时正确互传；②多于两个门时传到曼哈顿最近的那个；③并列距离时结果稳定；④传送后 AI 的来路为空，可朝入口方向走回；⑤场上只有一个门时踩过去等于普通路格、正常通过。

### RE-11 传送门失效（P0）
- **需求**：传送发生后**入口与出口两端同时**标记为已消耗，之后都变普通路格；消耗状态存于棋盘根状态表，**不得写进 SO 资产**。
- **验收**：`A→B` 之后再次踩 A 与踩 B 均不传送；退出 Play 再进 Play，两门恢复可用（证明状态没落到 SO 上）；一关 4 个门时最多传送 2 次。

### RE-12 AI 单步流程改造（P0）
- **需求**：`BoardRunModel.Step()` 按 4.4 改造，新增 `_forcedDirection` 一次性字段；效果只通过 `TileEffectResult` 影响 AI。
- **验收**：强制转向格后的那一步严格按强制方向走；传送不导致 AI 卡死或误判胜负；原有「无效果关卡」的行走结果与改造前**完全一致**（回归）。

### RE-13 效果图标视图（P1）
- **需求**：`BoardTile` 生成/刷新时在格子上叠一个 `SpriteRenderer` 子物体显示 `effect.Icon`（`sortingOrder` 高于格子层）；已消耗的效果图标置灰或隐藏。
- **验收**：带效果的格子肉眼可辨；传送后两端图标同步变为已消耗样式；重开本关后图标恢复。

### RE-14 关卡画笔支持效果（P1）
- **需求**：`BoardLevelPainter` / 其 Inspector 增加效果配置入口（选中若干格后批量赋同一个效果资产），并支持一键清空效果层。
- **验收**：批量给 5 个格赋 `Force_Right`，点「应用到子物体」后 5 个格子的 `effect` 字段均为该资产。

### RE-15 旧枚举迁移（P0）
- **需求**：`CellEffect` 枚举与 `BoardTile.effect` 枚举字段整体下线，替换为 `TileEffect` 资产引用；对已配过的场景做一次性迁移（旧枚举值落到无效果，或按映射建对应资产）。
- **验收**：迁移后工程 0 编译错误；`Level_01` 与 `BoardStep20` 两个场景打开无 Missing Reference；第一版全链路回归通过。

### RE-16 重开与重玩时效果状态复位（P0）
- **需求**：`RestartLevel()` 与结算面板「重玩此关」走 `BoardRoot.ResetEffectStates()`，清空全部消耗标记并重建运行时数组。
- **验收**：传送过一次后重开，两门重新可用；重开后棋盘根数据与首次进入关卡逐格一致。

### RE-17 扩展点验证（P0）
- **需求**：新增一个效果**不允许**修改 `BoardRoot` / `BoardRunModel` / `BoardTile` 任何一行代码（只能加新类 + 新资产 + 加进权重表）。
- **验收**：按第 5 节清单现场新增一个「位移」效果（沿前进方向推 2 格）并接进某关，全流程可用，改动文件仅限新增文件与配置资产。

### RE-18 表现与音效（P2）
- **需求**：效果触发时有视觉反馈（传送闪光 / 转向箭头闪动）与独立音效，音经受设置面板音效滑条控制。
- **验收**：两种效果各有可观测反馈；音量滑条实时生效。

## 7. 非功能需求

- 效果对象为 `ScriptableObject` 资产，**运行期零分配**（不 `Instantiate`、不 `new`）；每步最多构造 1 个 `ctx` 结构体。
- 传送门查找在 20×20 = 400 格内为**一次线性扫描**，单步开销不可感知；不引入每帧全局搜索。
- 全量 `Refresh()` 只在落盘 / 加载 / 重开时执行（一关最多约 50 次），运行期每步**不做**全量重建。
- 全部效果参数数据驱动：新增效果不改代码、不改场景结构。
- 效果不得抛异常终止 AI 流程；任何异常边界（越界 / 空资产 / 空图标）一律退化为「无效果」。
