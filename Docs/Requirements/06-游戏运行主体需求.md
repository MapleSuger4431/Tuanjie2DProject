# 06 · 游戏运行主体需求（铺路行走解谜）

> 游戏运行主体（`Game`）的核心玩法：15×15 棋盘上用俄罗斯方块式随机方块**铺路**，铺完后点击 Play，AI 按**局部规则**从起点走向终点。
> 基线设定见 [README](README.md)。优先级：P0 必须 / P1 重要 / P2 可选。
> 编写日期：2026-10-17 ｜ 状态：初稿，待团队评审

> ⚠️ **方案关系**：本篇为**新玩法方案**，与 [03 篇](03-游戏运行场景需求.md)（8×8 国际象棋回合制解谜）互为**互斥**的玩法方案，二者只能取其一。
> 在本文档评审定稿前，03 篇暂停实施；03 篇中的 HUD 外壳（结算/暂停/重开）定义本篇直接引用复用。

## 1. 范围

- `Game` 场景内的主体玩法：棋盘生成、方块虚影与放置、格子状态与覆盖规则、铺路/运行两阶段流程、AI 逐步行走、格子特殊效果、起点终点与胜负判定。
- **不包含**：主菜单与选关（01 / 02 篇）、成就判定本身（04 篇，本篇只负责发事件）、存档读写实现（05 篇）。
- 本篇**替代** 03 篇的玩法部分；暂停菜单 / 结算 / 重开等通用流程复用 03 篇的 GP-08 / GP-09 / GP-10 / GP-11 定义，不重复编写。

## 2. 玩法基线规则（评审时可调整，调整须同步改验收标准）

| 项 | 基线设定 |
|---|---|
| 棋盘 | 15×15 固定网格，Sprite 格子渲染，尺寸与间距可配置 |
| 操作 | 鼠标移动 → 方块虚影跟随；左键点击 → 放置 |
| 方块 | 3×3（九宫格）范围内的**四邻连通**格集合，每块 2–5 格 |
| 方块上限 | 每关最多刷新 **50** 块；用完后不再刷新，玩家须点击 Play |
| 格子状态 | 块内**每一格**自带：`陆地` / `火` / `冰` / `空` / `禁止` |
| 特殊效果 | `强制方向` / `连跳` / `属性转换` / `传送门` |
| AI | **不做全局寻路**；铺路完成后点击 Play，AI 按局部规则逐步行走 |
| 阶段 | `Building` 铺路阶段 → `Running` 运行阶段 |
| 胜负 | AI 抵达终点 = 胜利；AI 停下且未达终点 = 失败 |

## 3. 数据模型与规则

### 3.1 棋盘与格子

- 棋盘 `Board` 为 15×15 = 225 格；坐标 `(x, y)`，x 为列（0–14，左→右），y 为行（0–14，下→上）。
- 每个棋盘格 `BoardCell` 由**两层**构成：

| 层 | 字段 | 取值 | 说明 |
|---|---|---|---|
| 基底层 | `BaseType` | `Void` / `Forbidden` / `Start` / `Goal` | 关卡生成时确定，运行期不变 |
| 铺设层 | `TileState` + `TileEffect` | 见 3.2 / 3.5 | 由方块落下写入，初始为 `None` |

- `Void` 未铺设：初始默认，**不可行走，可被方块覆盖**。
- `Forbidden` 关卡预置禁区：**不可覆盖**（可由关卡配置，如固定岩石）。
- `Start` / `Goal` 起点与终点：唯一，**不可覆盖**，AI 可站立。

### 3.2 格子状态 `TileState`（方块内每格，落定时写入）

| 状态 | 可通行 | 可被后续方块覆盖 | 说明 |
|---|---|---|---|
| `Land` 陆地 | ✅ 任何属性 AI 均可通行 | ✅ | 通用路面 |
| `Fire` 火 | ✅ 仅**火人**可通行 | ✅ | 元素路面 |
| `Ice` 冰 | ✅ 仅**冰人**可通行 | ✅ | 元素路面 |
| `Hollow` 空 | ❌ 不可通行 | ✅ | 视觉为洞，允许被后续方块再覆盖 |
| `Ban` 禁止 | ❌ 不可通行 | ❌ | 落定后成为永久障碍（钉死该格） |

> 待定项：`Ban` 是否可通行。当前基线取「不可通行 + 不可覆盖」。

### 3.3 覆盖规则（放置合法性判定）

放置时按块内**每一格**逐格判定；**任一格非法则整块不可放置**：

| 目标格基底 | 目标格现有铺设层 | 可覆盖 |
|---|---|---|
| `Void` | `None` / `Hollow` / `Land` / `Fire` / `Ice` | ✅ |
| `Void` | `Ban` | ❌ |
| `Forbidden` | 任意 | ❌ |
| `Start` / `Goal` | 任意 | ❌ |
| 越界（棋盘外） | — | ❌ |

### 3.4 基础移动

- 基础通行方向为**四邻接**（上 / 下 / 左 / 右），**不走斜向**。
- AI 每一步从当前格移动到相邻的可通行格。

### 3.5 特殊效果 `TileEffect`（每格 0–1 个，不可叠加）

| 效果 | 触发时机 | 行为 |
|---|---|---|
| `ForceDirection` 强制方向 | AI 踏入该格后 | 下一步被**强制**朝箭头方向（↑↓←→）移动一格 |
| `DoubleJump` 连跳 | AI 踏入该格后 | 沿当前前进方向**跳跃 2 格**；中间格不结算效果、不要求可通行；按落点格正常判定 |
| `ElementSwitch` 属性转换 | AI 踏入该格后 | 元素属性翻转（火 ↔ 冰） |
| `Portal` 传送门 | AI 踏入该格后 | 传送到棋盘上**距离最近**的另一个传送门格 |

边界处理（MVP 默认值，见待定项）：

- 强制方向指向不可通行格 / 越界 → AI 停下 → 判负。
- 连跳落点不可通行 / 越界 → AI 停在起跳格 → 判负。
- 传送门不存在配对目标 → 效果不触发，AI 正常停留于该格。
- 同一格最多 1 个效果，不允许叠加。

### 3.6 AI 移动模型（**规则驱动，不做全局寻路**）

> **核心原则**：AI 不会计算到终点的路径。玩家把路铺好后点击 Play，AI 从起点出发，**每一步只看当前格的局部情况**决定走哪一格。
> 玩家的解谜乐趣来自：用格子状态、特效与岔路布局**引导** AI 走到终点。

**单步决策流程**：

```
1. 若上一步踏入的格子带有「强制方向」
   → 本步必须朝该方向走（优先级最高，直接跳过第 2 步）
   → 该方向不可走（越界 / 不可通行）→ AI 停下 → 判负

2. 否则计算候选方向集合，须同时满足：
   · 目标格在棋盘内
   · 目标格按 AI 当前元素属性可通行（见 3.7）
   · 目标格不是「来路格」——绝对禁止 180° 掉头

3. 候选集合为空 → AI 停下 → 判负（该路径设计失败）

4. 候选只有 1 个 → 走它

5. 候选 ≥ 2（岔路口 / 三岔 / 四岔）→ 按「偏好方向优先级顺序」
   取第一个落在候选集合中的方向

6. 移动到目标格后，结算该格的特效（属性转换 / 连跳 / 传送门 / 强制方向）
```

**禁止掉头**：AI 任何情况下都不能走回头路（180° 掉头）。
「禁止掉头」即「没有路可走 = 这条路设计失败」——除来路外无其它可走格时，AI 停下并判负。

**偏好方向优先级顺序**由三层配置组合而成：

| 配置项 | 取值 | 默认 |
|---|---|---|
| 轴优先级 `AxisPriority` | `Horizontal`（先左右） / `Vertical`（先上下） | `Horizontal` |
| 左右偏好 `HorizontalPreference` | `Right` / `Left` | `Right` |
| 上下偏好 `VerticalPreference` | `Up` / `Down` | `Up` |

默认顺序（**横向大于纵向**）：`右 → 左 → 上 → 下`

- 先看左右轴，再看上下轴；左右中先右后左，上下中先上后下。
- 三岔、四岔路口统一按此顺序取第一个**可走**的方向，结果唯一、无歧义。
- 该三项属于关卡配置，HUD 上常驻展示当前值（见 RB-22）。

**结算顺序**：一步之内先移动到位，再结算落点格特效；特效产生的位移（连跳 / 传送）在同一 tick 内完成，落点格再结算其自身特效。

### 3.7 AI 元素属性

- AI 携带元素属性（火人 / 冰人），初始值由关卡配置。
- 可通行判定：`Land` 任意属性可走；`Fire` 需火属性；`Ice` 需冰属性；`Hollow` / `Ban` / 未铺设格一律不可走。
- `ElementSwitch` 特效翻转属性，翻转后**立即**影响后续每一步的通行判定。

### 3.8 阶段划分

| 阶段 | 进入方式 | 允许操作 |
|---|---|---|
| `Building` 铺路阶段 | 关卡加载后默认进入 | 鼠标虚影、放置方块、点击 Play |
| `Running` 运行阶段 | 铺路阶段点击 Play | **禁止放置**；AI 逐步行走；可暂停 |

- 运行阶段不可回到铺路阶段（除非重开 / 重试）。

## 4. 核心循环

```
进入关卡 → 生成 15×15 棋盘（含起点 / 终点 / 预置禁区）
  → 生成首个方块，进入 Building 阶段
  ┌─ 玩家移动鼠标：虚影居中跟随，高亮将覆盖的格子（合法=绿，非法=红）
  │  左键点击：合法则写入铺设层 → 消耗当前方块 → 下一个变当前 → 新生成下一个
  └─ 重复铺路（最多 50 块；用完后不再刷新）
  → 玩家点击 Play → 进入 Running 阶段，禁止放置
  → AI 从起点按 3.6 逐步行走（强制方向 > 偏好方向，禁止掉头）
  → AI 抵达终点 → 胜利结算
  → AI 停下且未达终点 → 失败结算（【重试】保留已铺棋盘 /【返回选关】）
```

## 5. 界面元素（HUD）

- **左上角**：下一个方块预览（形状 + 每格状态色 + 特效图标）
- **跟随鼠标**：当前方块虚影（半透明），覆盖将影响的格子区域
- **棋盘**：合法性高亮（可放 = 绿 / 正常色，不可放 = 红）
- **顶部**：已放置方块数 `已用/50`、AI 当前元素属性标识（火 / 冰）、**偏好方向指示器**（三项配置）
- **Play 按钮**：铺路阶段可用，点击进入运行阶段；方块用完后突出提示
- **弹层**：暂停菜单、胜利结算、失败面板（复用 03 篇 GP-10 / GP-08 / GP-09）

## 6. 功能需求

---

### RB-01 棋盘生成（P0）
- **需求**：进入场景后用 Sprite 生成 15×15 棋盘，格子大小与间距可配置；按关卡配置写入预置禁区 `Forbidden`、起点 `Start`、终点 `Goal`。禁止在场景里手工摆放格子。
- **验收**：棋盘 225 格完整无缺；坐标与配置一致；起点与终点唯一且不可被覆盖。

### RB-02 基础格子、起点、终点（P0）
- **需求**：实现 `BoardCell` 数据（基底层 + 铺设层 + 效果槽）；起点与终点为特殊格，不可被方块覆盖、AI 可站立，并有专属视觉标识。
- **验收**：数据字段与 3.1 / 3.2 / 3.5 一致；在起点或终点上放置任意方块均判非法（虚影变红且点击无效）。

### RB-03 方块形状定义（P0）
- **需求**：方块形状定义为 **3×3（九宫格）范围内的四邻连通格集合**，格数 2–5。形状以 `Vector2Int` 偏移列表配置于 ScriptableObject 形状表，可配权重。
- 已枚举的可用形状总数（含朝向，按平移归一，实测）：

  | 格数 | 形状数 |
  |---|---|
  | 2 | 2 |
  | 3 | 6 |
  | 4 | 17 |
  | 5 | 37 |
  | **合计** | **62** |

- **验收**：形状表加载时校验——全部形状四邻连通、包围盒 ≤ 3×3、格数 ∈ [2, 5]；增删形状无需改代码。

### RB-04 方块随机生成（P0）
- **需求**：生成方块时分两步随机：① 按权重抽取形状（RB-03）；② 为块内**每一格**独立随机状态（`Land` / `Fire` / `Ice` / `Hollow` / `Ban`）与 0–1 个特殊效果。各状态与效果的抽取权重可配置。
- **验收**：指定随机种子生成 1000 次，格数分布与形状权重一致、每格状态分布与配置权重一致（±5%）；同种子结果可完全复现。

### RB-05 鼠标虚影跟随与锚点（P0）
- **需求**：鼠标在棋盘区域移动时，当前方块以**锚点格对齐鼠标所在格**实时显示半透明虚影，呈现将覆盖的格子区域；虚影需显示每格的状态色与特效图标。
- **锚点规则**：
  - 形状包围盒宽、高**均为奇数** → 锚点 = 几何中心格；
  - 否则（任一维为偶数，如 2×2）→ 锚点 = 包围盒**左上角**格。
- **验收**：锚点格 = 鼠标悬停格，且形状按上表规则对齐；形状与当前方块一致；鼠标移出棋盘时虚影隐藏；2×2 块以左上角格对齐鼠标为基准向右下展开。

### RB-06 放置合法性判定与反馈（P0）
- **需求**：按 3.3 覆盖规则实时判定；合法时虚影为绿（或正常色），非法时为红并禁止放置。
- **验收**：对 `Ban`、`Forbidden`、`Start`、`Goal`、越界五种非法情形均正确变红且点击不生效；块中任一格越界即整块判非法。

### RB-07 放置与刷新（P0）
- **需求**：左键点击合法位置即放置：把块内每格的状态与特效写入对应棋盘格的铺设层；放置后消耗当前方块，队列中的「下一个」变为当前，并新生成一个「下一个」。
- **验收**：放置后棋盘铺设层数据与方块数据逐格一致；刷新后左上角预览与新当前块完全一致；放置计数 +1。

### RB-08 下一块预览（P0）
- **需求**：屏幕左上角常驻显示下一个方块预览：形状、每格状态色、特效图标；尺寸与棋盘格子成比例。
- **验收**：预览内容与即将切换进来的当前方块 100% 一致（形状、每格状态、每格特效）。

### RB-09 AI 元素属性与通行判定（P0）
- **需求**：AI 携带元素属性（火人 / 冰人），初始值由关卡配置；按 3.7 判定每格可否通行。
- **验收**：火人可走 `Land` + `Fire`、拒走 `Ice`；冰人可走 `Land` + `Ice`、拒走 `Fire`；`Hollow` / `Ban` / 未铺设格一律不可走；`ElementSwitch` 后立即改变判定结果。

### RB-10 AI 逐步移动决策（P0）
- **需求**：按 3.6 实现单步决策：**强制方向 > 偏好方向**；候选方向须排除来路格（绝对禁止掉头）；候选为空则停下判负；岔路口按偏好优先级顺序取第一个可走方向。
- **验收**：
  1. 单向通路：AI 沿唯一路径直行，不偏不倚。
  2. 岔路口：构造四岔、三岔、二岔各一，AI 选择结果与默认顺序 `右→左→上→下` 一致；把轴优先级改为 `Vertical` 后结果随之改变。
  3. 掉头：AI 面对来路 + 死路时停下判负，**不**掉头返回。
  4. 死循环：AI 不会在两格之间来回振荡。

### RB-11 AI 行走表现（P0）
- **需求**：AI 按决策逐格移动（补间动画 ≤ 200ms/格），经过特效格时触发对应效果并给出视觉反馈；行走过程可暂停。
- **验收**：四种特效各有可观测的正确行为；属性转换后 AI 外观与可通行判定同步更新；暂停时行走与动画停止。

### RB-12 特效 · 强制方向（P0）
- **需求**：格子带方向箭头（↑↓←→），AI 踏入后下一步被强制朝该方向移动一格；**优先级高于偏好方向与掉头禁令**，为该格唯一决策依据。
- **验收**：四种方向各自生效，且能覆盖偏好方向（即使偏好方向也可走，仍走强制方向）；指向不可通行格或越界时 AI 停下判负，不崩溃、不穿墙。

### RB-13 特效 · 连跳（P0）
- **需求**：AI 踏入后沿当前前进方向跳跃 2 格；中间格不结算效果、不要求可通行。
- **验收**：净位移恰为 2 格；落点按普通规则判定并结算其特效；落点不可通行时 AI 停在起跳格并判负。

### RB-14 特效 · 属性转换（P0）
- **需求**：AI 踏入后元素属性翻转（火 ↔ 冰）。
- **验收**：翻转后立即影响后续通行判定（原不可走的冰/火路变为可走）；AI 外观同步切换。

### RB-15 特效 · 传送门（P0）
- **需求**：AI 踏入后传送到距离最近的另一个传送门格。
- **验收**：存在多个传送门时传送到最近的一个；无配对目标时效果不触发；传送落点按普通规则判定。

### RB-16 运行阶段与 Play 流程（P0）
- **需求**：HUD 提供 Play 按钮；点击后从 `Building` 切到 `Running`，**锁定放置**（虚影隐藏、点击棋盘无效），AI 从起点开始逐步行走直到抵达终点或停下。
- **验收**：运行阶段任何放置尝试均无效；Play 按钮在运行阶段置灰；AI 出发位置为起点格。

### RB-17 方块数量上限（P0）
- **需求**：每关最多刷新 **50** 个方块，HUD 常驻显示 `已用/50`；达到 50 后**不再刷新**下一个（当前块放置完即无块可用），并突出提示玩家去点击 Play。
- **验收**：放置第 50 块后预览区显示为空且不可再放置；**用尽方块本身不判负**——只有 Play 后 AI 未抵达终点才判负。

### RB-18 胜负判定与结算（P0）
- **需求**：
  - **胜利**：AI 抵达终点，锁定输入、播放胜利反馈，弹出结算面板（用块数、按钮组【重玩】【下一关】【返回选关】）；结果写入存档并向成就系统发「通关」事件（含关卡 ID、用块数）。
  - **失败**：AI 停下且未抵达终点——包括无合法下一步（死路）、强制方向指向不可通行格、连跳落点不可通行。弹出失败面板【重试】【返回选关】。
- **验收**：①抵达终点立即判胜；②三条失败路径分别可触发且不误判；③最后一关通关时「下一关」隐藏或替换为「返回选关」。

### RB-19 重开与重试（P0）
- **需求**：
  - **重试**（失败面板）：回到 `Building` 阶段，**保留已铺棋盘**、已用方块数与 AI 初始状态，供玩家继续铺路或调整后再次 Play。
  - **重开本关**（暂停菜单 / 结算面板）：完全重置棋盘铺设层、方块队列、AI 位置与属性，不改存档历史成绩。
- **验收**：重试后棋盘与失败前逐格一致、计数不变；重开后与首次进入一致；历史成绩保留。

### RB-20 暂停菜单（P0）
- **需求**：复用 03 篇 GP-10 定义（暂停按钮 / Esc 打开，游戏时间暂停、输入屏蔽，【继续】【重开本关】【设置】【返回选关】）；运行阶段暂停时 AI 行走一并停止。
- **验收**：暂停时 AI 行走与动画停止，任何棋盘点击无效。

### RB-21 偏好方向 HUD 指示（P0）
- **需求**：HUD 常驻展示当前关卡的偏好方向配置：轴优先级（先左右 / 先上下）、左右偏好、上下偏好，以方向图标或文字呈现，并在运行阶段高亮 AI 当前实际选用的方向。
- **验收**：HUD 数值与关卡配置一致；改变配置后 AI 在岔路口的选择同步改变。
- 待定：是否允许玩家在运行过程中修改该配置（当前基线为关卡配置、局中只读）。

### RB-22 输入适配（P0）
- **需求**：全部操作仅使用 Input System（遵循项目输入约定）；鼠标为主操作方式。
- **验收**：无 `Input.*` 旧 API 调用；鼠标移动 / 左键点击 / Play 按钮全流程可用。

### RB-23 音效反馈（P1）
- **需求**：放置、非法提示、AI 每步移动、属性转换、传送、连跳、胜利、失败、UI 点击各有独立音效；音经受设置面板音效滑条控制。
- **验收**：各事件触发对应音效；音量滑条实时生效。
