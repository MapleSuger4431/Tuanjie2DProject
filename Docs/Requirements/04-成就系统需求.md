# 04 · 成就系统需求

> 给玩家长期目标与收集乐趣：定义成就、判定解锁、弹出通知、提供列表界面，并随存档持久化。
> 基线设定见 [README](README.md)。优先级：P0 必须 / P1 重要 / P2 可选。

## 1. 范围

- 成就数据定义、解锁判定、解锁通知、成就列表界面、成就状态持久化。
- **不包含**：成就图标的美术制作（本文只定义规格）；平台成就对接（Steam / Google Play Games，见待定项）。

## 2. 与玩法方案的关系（⚠️ 重要）

当前玩法存在 03 篇（方案 A：国际象棋回合制）与 06 篇（方案 B：铺路寻路）两套互斥候选。本系统按**方案无关**设计：

- 成就条件只消费统一的游戏事件与统计计数（见 AC-03），不直接依赖任何玩法的内部实现。
- 事件中的"成绩数值"语义由玩法方案决定：方案 A 为**通关步数**，方案 B 为**通关用块数**；成就条件统一以"成绩 ≤ 阈值"表达。
- 第 7 节 MVP 清单分「通用成就」（两方案共用）与「方案专属成就」（随定稿方案启废）。

## 3. 数据结构

### 3.1 成就定义（配置，ScriptableObject 或 JSON 表）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一标识，如 `first_clear`；入库后不可改名 |
| `name` | string | 显示名称（中文） |
| `description` | string | 解锁条件描述（对玩家可见；隐藏成就解锁前显示"???"） |
| `icon` | Sprite | 图标；未解锁时置灰显示 |
| `type` | enum | `Event` 事件型 / `Counter` 计数型（见 AC-03） |
| `eventKey` | string | Event 型：监听的事件名（如 `LevelCleared`） |
| `threshold` | int | 条件参数：成绩阈值或计数目标值 |
| `compare` | enum | `LessOrEqual` / `GreaterOrEqual`，配合 threshold 使用 |
| `hidden` | bool | 隐藏成就：解锁前在列表中只显示占位 |

### 3.2 成就状态（运行时 + 存档）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 对应定义 |
| `unlocked` | bool | 是否已解锁 |
| `unlockTime` | string (ISO 8601) | 解锁时间，本地时间 |
| `progress` | int | 计数型成就的当前进度（事件型恒为 0/1） |

## 4. 功能需求

### AC-01 成就定义加载（P0）
- **需求**：成就全部以配置表定义（数据驱动），游戏启动时加载并校验：id 唯一、icon 非空（可先用占位图）、type 与字段组合合法。新增成就不改代码。
- **验收**：配置 N 条成就则运行时存在 N 条定义；重复 id 或非法配置在编辑器下报错并指出具体条目。

### AC-02 解锁判定 · 事件型（P0）
- **需求**：监听统一游戏事件（经 Events 模块），事件发生时按 `compare + threshold` 判定并解锁。MVP 事件集：
  - `LevelCleared(levelId, score, stars)`：通关某关（score 语义见第 2 节）
  - `LevelFailed(levelId)`：某关失败
  - `GameFirstLaunched`：首次进入主菜单
- **验收**："通关第 1 关"类成就在通关结算出现的同一帧完成解锁判定；条件不满足时不解锁。

### AC-03 解锁判定 · 计数型（P0）
- **需求**：系统维护一组累计计数器（持久化在存档中，见 05 篇）：总通关数、总星数、总局数（进入关卡即计）。每次计数器变化时检查所有绑定该计数器的成就，达到 `threshold` 即解锁；`progress` 同步更新用于列表展示进度。
- **验收**：以"累计通关 10 关"为例，第 10 次通关时解锁；计数跨会话累计（重启游戏不清零）；列表中未解锁时显示当前进度（如 7/10）。

### AC-04 解锁通知（P0）
- **需求**：成就解锁时弹出通知横幅（屏幕上方滑入，显示图标 + "成就解锁" + 名称，停留约 3 秒后滑出）；游戏中、结算界面、主菜单中均可弹出；多个成就同时解锁时排队依次播放，不重叠。
- **验收**：解锁即见通知；连续解锁 3 个成就时 3 条通知依次完整播放；通知不阻断当前操作（不可点击、不抢输入焦点）。

### AC-05 成就列表界面（P0）
- **需求**：从主菜单「成就」按钮打开（叠加面板）：列表展示全部成就——已解锁的显示彩色图标 + 名称 + 描述 + 解锁日期；未解锁的显示置灰图标 + 名称 + 描述 + （计数型）进度条；隐藏成就解锁前整行显示"???"。顶部显示完成度 x/y。
- **验收**：列表状态与存档一致；完成度计数正确；隐藏成就解锁前不泄露名称与描述。

### AC-06 防重复解锁（P0）
- **需求**：已解锁的成就不再触发判定与通知；重启游戏后已解锁状态保持。
- **验收**：重复满足同一条件不出现第二次通知；存档中 `unlocked` 与 `unlockTime` 不被覆盖。

### AC-07 解锁通知的显示时机约束（P1）
- **需求**：通知横幅避开关键演出时机：结算面板打开期间解锁的成就，通知延迟到结算面板关闭后播放。
- **验收**：通关同时解锁成就时，先完整看到结算面板，关闭后通知正常播放，不丢失。

### AC-08 调试后门（P1，仅编辑器/开发包）
- **需求**：提供调试手段：一键解锁指定成就、一键重置全部成就状态（不写进正式包或需特定开启方式）。
- **验收**：编辑器下可通过调试菜单触发；正式构建中该入口不可达。

## 5. 非功能需求

- 成就判定不得产生可感知卡顿（单次判定的成就数量 ≤ 100 时耗时可忽略）。
- 通知横幅动画流畅，与玩法画面叠加不引起掉帧。

## 6. 边界与异常

| 情况 | 期望行为 |
|---|---|
| 存档损坏重建 | 成就状态按全新存档处理（全部未解锁），计数器归零 |
| 配置表删除了已解锁的成就 id | 加载时忽略存档中的孤儿数据，不报错；可选在日志中警告 |
| 一局内满足多个成就 | 全部解锁，通知排队播放（AC-04） |
| 计数器回退（如重开不算通关） | 计数器只增不减；成就一旦解锁不因任何后续操作回退 |
