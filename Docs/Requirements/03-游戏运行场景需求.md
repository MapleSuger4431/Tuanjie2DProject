# 03 · 游戏运行场景需求

> 核心玩法所在：玩家在一个手工设计的棋盘谜题关卡中，按回合制走棋，达成关卡目标。
> 本篇是五篇中篇幅最大、优先级最高的一篇。基线设定见 [README](README.md)。

## 1. 范围

- `Game` 场景内的全部玩法与交互：棋盘生成、走棋、胜负判定、结算、暂停。
- 关卡数据的消费方式（数据结构由程序定义，关卡内容由策划填写）。
- **不包含**：选关与解锁（02 篇）、成就解锁判定（04 篇，本篇只负责抛事件）、存档读写实现（05 篇）。

## 2. 玩法基线规则（⚠️ 团队评审后可调整）

以下规则是需求落地的基线假设，**不是最终设计**；调整时同步修订本篇：

- **回合制**：玩家先手，每个己方回合移动一枚棋子一步；MVP 阶段敌方棋子**静止不动**（纯解谜），敌方按规则行动为 P1 扩展（见 GP-17）。
- **走法**：遵循国际象棋基本走法（车/马/象/后/王/兵）。MVP **不含**王车易位、吃过路兵、兵的升变（见待定项）。
- **吃子**：移动到敌方棋子所在格即吃掉，被吃棋子移出棋盘。
- **关卡目标**（每关配置其一，MVP 三种）：
  1. **歼灭**：吃掉全部敌方棋子；
  2. **斩首**：吃掉（将杀）敌方王；
  3. **抵达**：己方指定棋子到达目标格。
- **步数限制**（每关可选配置）：超过上限仍未达成目标则失败。
- **星级评价**：每关配置 3 星 / 2 星步数阈值，通关步数 ≤ 3 星线得 3 星，≤ 2 星线得 2 星，其余通关得 1 星。无步数限制的关卡按同一套阈值评星。
- **棋盘**：矩形网格，每关尺寸可变（≤ 8×8，支持缺角/空洞格）；可配置障碍格（不可进入）。

## 3. 核心循环

```
进入关卡 → 展示目标面板 → 玩家走棋（选中→高亮→移动）→ 每步后判定胜负
  → 胜利：结算界面（星级/步数）→ 下一关 / 重玩 / 返回选关
  → 失败：失败界面 → 重试 / 返回选关
```

## 4. 界面元素（HUD）

- 顶部栏：关卡编号与名称、当前步数（有上限时显示"已用/上限"）、暂停按钮
- 目标提示按钮（局中随时查看目标）
- 棋盘区：居中的棋盘与棋子、选中高亮、可走格标记
- 结算/失败/暂停三个叠加面板

## 5. 功能需求

### GP-01 关卡加载与棋盘生成（P0）
- **需求**：进入场景时按关卡配置数据生成棋盘（尺寸、缺角、障碍格、特殊格纹理）与双方棋子（棋种、位置、阵营）；数据驱动，新增关卡不改代码。
- **验收**：加载任一配置关卡，棋盘尺寸/格子状态/棋子位置与配置完全一致；配置缺失字段时使用默认值且不报错。

### GP-02 棋子选中与可走格高亮（P0）
- **需求**：点击己方棋子进入选中态（棋子高亮/描边），并按该棋种走法高亮全部合法目标格：纯移动格用点标记，可吃子格用角标/异色标记（参照美术调研的"角标编码"手法）；不合法格（越界、障碍、己方子占据）不高亮。
- **验收**：对每个棋种（车/马/象/后/王/兵）抽查典型局面，高亮集合与规则推导的合法走法完全一致（建议落地为可自动化断言的走法单测）。

### GP-03 移动执行与动画（P0）
- **需求**：点击高亮格执行移动：棋子以补间动画平滑移动到位（时长 ≤ 300ms），动画期间锁定输入；移动完成后步数 +1 并进入胜负判定。
- **验收**：移动无瞬移/穿格；动画中点击无效；步数计数正确。

### GP-04 吃子与反馈（P0）
- **需求**：移动到敌子格时，敌子播放被吃反馈（缩小/淡出或爆裂占位效果）后移除，同时播放吃子音效；被吃子不再参与任何判定。
- **验收**：吃子后棋盘状态正确（敌子移除、己子到位）；被吃子不可再被选中或阻挡走法。

### GP-05 取消选择（P0）
- **需求**：选中棋子后，点击棋盘空白处/再次点击该棋子/按 Esc，取消选中并清除高亮。
- **验收**：三种取消方式均生效；取消后点击其他己方子可直接改选。

### GP-06 步数计数与显示（P0）
- **需求**：每完成一次己方移动计 1 步；HUD 实时显示；有上限的关卡显示"已用/上限"并在剩余 ≤ 3 步时做醒目提示（变色）。
- **验收**：步数与实际移动次数一致；剩余步数提示按阈值出现。

### GP-07 目标展示（P0）
- **需求**：进入关卡时弹出目标面板（目标类型 + 步数限制 + 星级线），点击"开始"进入操作；局中可通过 HUD 按钮随时重看目标（暂停计时/不暂停均可，默认不暂停）。
- **验收**：目标面板内容与关卡配置一致；局中可重复查看。

### GP-08 胜利判定与结算（P0）
- **需求**：每步完成后按关卡目标判定：达成即进入结算——播放胜利反馈，显示结算面板：星级（0–3 取最高写入存档）、用步数、按钮『下一关』『重玩』『返回选关』；同时向成就系统抛"通关"事件（04 篇）并将星级写入存档（05 篇）。
- **验收**：三种目标类型各抽查一关，达成即正确触发结算；星级按阈值计算正确；『下一关』加载第 N+1 关（已是最后一关时该按钮变为"返回选关"）。

### GP-09 失败判定与失败界面（P0）
- **需求**：失败条件（任一即败）：步数用尽仍未达标；己方王被吃（斩首类关卡中若配置己方王）；己方无任何合法走法（死局）。失败后显示失败面板：『重试』『返回选关』。
- **验收**：三种失败条件分别构造局面验证触发正确；失败面板按钮可用。

### GP-10 暂停菜单（P0）
- **需求**：点击 HUD 暂停按钮或按 Esc 打开暂停面板（叠加，游戏逻辑冻结）：『继续』『重开本关』『设置』（音量两项，同主菜单设置）『返回选关』。
- **验收**：暂停期间棋子不可选中/移动；各按钮功能正确；返回选关不保存本关中途进度（只有通关才写星级）。

### GP-11 重开本关（P0）
- **需求**：从暂停/结算/失败面板均可重开：棋盘恢复到本关初始状态，步数清零。
- **验收**：重开后棋子位置、步数、目标状态与首次进入完全一致；可连续重开无状态残留。

### GP-12 悔棋（P1）
- **需求**：HUD 提供"悔棋"按钮，撤销上一步己方移动（连同被吃的敌子一起还原）；悔棋**不计步数**（步数回退 1）；可连续悔棋至开局。
- **验收**：悔棋后棋盘状态与历史局面逐项一致；步数同步回退；开局状态再按悔棋无响应（或按钮置灰）。

### GP-13 下一关入口（P0）
- **需求**：结算面板『下一关』直接进入第 N+1 关（若已解锁——通关本关即解锁下一关，见 02 篇 LS-03）；最后一关通关后该位置显示"返回选关"。
- **验收**：通关第 N 关后点『下一关』正确加载第 N+1 关；最后一关行为符合描述。

### GP-14 输入适配（P0）
- **需求**：全部操作同时支持鼠标（左键点选）与触屏（点按）；不使用旧 Input API，遵循项目 Input System 约定。
- **验收**：PC 端鼠标全流程可玩通一关；Android 真机触屏全流程可玩通一关，无 Input 相关异常。

### GP-15 音效反馈（P1）
- **需求**：关键事件播放对应音效：选中、落子、吃子、胜利、失败、按钮点击；音量受设置面板音效滑条控制。
- **验收**：各事件音效正确触发；音量设置实时生效。
